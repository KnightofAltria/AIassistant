# 界面交互与移动端设计

## 体验目标与导航

用户每次进入课程都能知道“现在可以学什么、依据是什么、下一步做什么”。首页优先呈现学习目标和行动入口，不让图表压过学习任务。所有诊断使用尊重学生、可验证和可纠正的语言。

桌面左侧课程与导航，中间主内容，右侧按需打开出处或学习建议；手机为单列内容和底部“学习、提问、复习、我的”四项导航，更新入口显示小徽标。课程切换位于页首，切换时清晰显示课程名并清理上课会话上下文。

## 页面与状态

| 页面 | 核心内容 | 主操作 | 必须设计的状态 |
|---|---|---|---|
| 欢迎与课程选择 | 课程说明、加入码、使用模式 | 加入课程 | 无课程、无效加入码、网络失败 |
| 首次引导 | 目标、可跳过摸底、数据使用说明 | 开始学习 | 跳过、不支持云模式、隐私选择 |
| 学习首页 | 当前课程、今日3项建议、最近变化 | 开始一项任务 | 新用户无数据、任务完成、分析延迟 |
| 问答页 | 对话、提示层级、出处、后续问题 | 发送或停止 | 检索中、生成中、缺资料、超时、中断 |
| 引用详情 | 文档标题、版本、页码或段落、原文 | 返回回答 | 已更新、已撤回、权限不足 |
| 练习页 | 单题、提示、提交后反馈、验证题 | 提交答案 | 草稿、提交中、待复核、重复提交 |
| 学习面板 | 知识点表现、证据数、误区候选 | 查看证据或复测 | 证据不足、争议、重算中 |
| 复习页 | 到期任务、建议时长、复测结果 | 开始复习 | 空任务、过期、改期 |
| 更新中心 | 发布摘要、差异、来源、版本 | 查看变化 | 无变化、未读、已撤回 |
| 个人设置 | 模式说明、数据导出删除、缓存管理 | 保存设置 | 导出生成中、删除确认、已完成 |
| 课程维护台 | 资料、题库、知识点、候选、发布历史 | 审核或发布 | 解析失败、冲突、索引未就绪 |

## 核心页面线框

```text
手机问答页                            手机学习首页
┌────────────────────────┐         ┌────────────────────────┐
│ ‹ 统计基础        更新 ● │         │ 统计基础 ▾       个人设置 │
│ 当前资料 v12            │         │ 今天想先掌握哪一部分？   │
├────────────────────────┤         │ [继续昨天的学习]         │
│ 你：相关就意味着因果吗？ │         ├────────────────────────┤
│                        │         │ 建议复习  约 10 分钟     │
│ 先看两个变量是否可能由  │         │ 相关与因果  待验证       │
│ 同一因素影响…… [来源1]  │         │ 证据：2 道题 [查看证据]  │
│ [给个提示] [完整解释]   │         │ [做一道验证题]           │
│ [用一道题验证理解]      │         ├────────────────────────┤
├────────────────────────┤         │ 课程资料有 1 项更新      │
│ 输入问题…         发送  │         │ [查看变化]               │
├────────────────────────┤         ├────────────────────────┤
│ 学习   提问   复习   我的│         │ 学习   提问   复习   我的│
└────────────────────────┘         └────────────────────────┘
```

线框用于确认信息结构，不代表已实现视觉原型。问答引用在手机以全高抽屉或新页面打开，保留返回位置；不能依赖悬停才能查看出处。

## 视觉规范

采用温和清晰的学习工具风格。背景#F7F8FC，正文#182230，辅助文字#475467，主操作#2457D6，成功#167347，警示#975A00，错误#B42318；颜色最终需用对比度工具验证，正文对比目标至少4.5:1。状态同时用图标与文字表达。

正文16px、行高1.6，页面标题24至30px，桌面内容最大宽1200px，长文阅读区约760px；间距基于4、8、12、16、24、32px，卡片圆角12px。主操作每个区域尽量一个。避免堆叠渐变、重阴影和装饰性仪表盘。图表默认用条形和简单趋势，提供文字说明与数据表替代。

## 引导与异常文案

首次提问前给三类示例：“解释一个概念”“分步提示一道题”“检查我的理解”。缺资料：“当前课程资料中还没有找到足够依据。可以补充题目背景，或请维护者导入资料。”诊断延迟：“答案已保存，学习分析稍后更新。”模型不可用：“当前学习助手暂时无法回答，你的输入已保留。”

来源验证完成前显示“出处核验中”，不能先给已验证标记。流式答复中止时保留内容并标记未完成。用户切换页面应取消订阅但允许返回查看请求状态；停止生成则调用取消接口。

## 手机与PWA策略

断点初值<768px单列，768至1199px双栏，≥1200px可展开出处栏；360、390、768、1440px分别检查。输入框跟随可视视口，测试软键盘、安全区和横竖屏。代码、公式和宽表只在自身容器内滚动；非代码页面不得整体横向滚动。

PWA为首版安装形式，部署需HTTPS（本机开发例外），配置manifest、图标和离线页。安装体验因浏览器和系统不同，需分别提供引导并实机验证。[web.dev安装说明](https://web.dev/learn/pwa/installation)

默认仅缓存静态外壳和明确选择的公开课程资料。私人对话、题目答案、会话接口均network-only，不进入共享service worker缓存。离线仅可阅读已缓存公开资料和编辑本机作答草稿；在线推理、同步、网络更新均显示不可用。草稿恢复后由用户确认提交，不后台自动计分；退出登录删除按账号分区的草稿。

不承诺手机本地推理。手机访问电脑上的本地模型需通过同一局域网的受保护后端，HTTPS访问方案、证书信任和防火墙设置见部署文档。

## 无障碍与验证

所有表单有可见标签和错误关联；焦点顺序稳定，弹窗关闭后返回触发点。流式输出采用节流的aria-live摘要，避免逐token轰炸读屏。动画遵循减少动态偏好。选项和图标按钮有可读名称，核心任务支持全键盘。邀请3至5位非开发同学完成首次提问和复测任务，记录完成率、卡点和改版依据。
