## 2 测试方法

| 方法 | 用途 | 具体做法 |
|---|---|---|
| 自动化回归 | 每轮改动、交付前 | `check.py`（20 项，零成本）+ `selftest.py`（44 项，全链路） |
| 接口测试 | 验证 REST/SSE 契约 | 脚本按编号逐条请求，断言状态码、字段、事件顺序 |
| 功能测试 | 验证业务闭环 | 手工按用例走主流程，配合脚本断言数据库结果 |
| 等价类与边界值 | 参数校验 | 空值、超长、非法枚举、负数、不存在的 ID |
| 错误推测 | 健壮性 | 断网、Key 失效、端口占用、模型返回空、资料为空 |
| 静态检查 | 代码质量 | Python `py_compile`、JS `node --check`、重复声明扫描、HTML 配平 |
| 数据体检 | 数据一致性 | 查重复资料、过小资料、核心文件夹数量 |
| 目视检查 | 界面与排版 | 逐页对照 U1–U8 规范 |

**测试策略要点**

1. **能自动化的不放人工**：凡是能断言的全部进 `selftest.py`，人工只做视觉与体验判断。
2. **测试不污染用户数据**：`selftest.py` 结束自动清理会话/总结/错题/占位题/测试文件夹；日常改动只跑零成本的 `check.py`。
3. **缺陷必须回归**：每个修复都要补一条断言，避免复发（已补 2 条：前端重复声明、数据体检）。

### 3.1 测试环境

| 项 | 配置 |
|---|---|
| 操作系统 | Windows 11（主测）/ Windows 10 |
| Python | 3.10+（无第三方包） |
| 浏览器 | Chrome 120+ / Edge 120+ |

### 3.2 测试辅助工具

| 工具 | 用途 | 说明 |
|---|---|---|
| `app/check.py` | 静态 + 只读接口检查 20 项 | 零成本，5 秒内完成，不写库 |
| `app/selftest.py` | 全链路检查 44 项 | 约 7 次模型调用，结束自动清理 |
| `app/reindex.py` | 重建切片索引 | 用于验证索引一致性 |
| 浏览器 DevTools | 观察 SSE 帧、网络状态、控制台报错 | 手工 |
| `curl` | 单独验证接口 | 抓取兜底同一工具 |

### 3.3 环境预置步骤

```text
1. 复制程序目录到测试机，确认未安装任何第三方包
2. 双击 启动.bat，确认自动探测 Python 并打开浏览器
3. 在配置页填入 API Key，点击连通性测试
4. 运行 check.py，确认 20/20 通过
5. 需要全链路时再运行 selftest.py，确认 44/44 通过且数据回到基线
```

## 6 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 模型不稳定或限流 | 功能用例失败但非代码缺陷 | 记录为环境问题；用 `--mock` 区分代码问题与外部问题 |
| 测试数据污染用户库 | 用户投诉、数据失真 | 自检结束自动清理；日常只跑零成本检查 |
| 抓取站点结构变化 | 资料抽取失败 | 保留来源清单与 `--force` 重抓；正文过短即判失败 |
| 时间不足 | 用例执行不全 | 优先保证 P0/P1；未执行项在 K-3 如实列出 |
