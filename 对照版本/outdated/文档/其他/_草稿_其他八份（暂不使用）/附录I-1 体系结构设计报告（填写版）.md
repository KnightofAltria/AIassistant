## 1 系统概述

CSLA 是一个**单机运行的单体应用**：一个 Python 进程同时提供静态页面与 JSON/SSE 接口，前端为原生 JS 单页应用，数据保存在本地 SQLite 与文件中，模型能力通过 DeepSeek API 获取。

规模：后端 11 个 Python 文件约 3,400 行，前端 4 个 JS 文件约 1,600 行、1 个 CSS 约 630 行、1 个 HTML 约 360 行；数据库 13 张表。

核心能力：资料导入与索引 → 检索与证据组装 → 带引用的流式问答；按科目章节学习与练习；模型通过 15 个工具修改本地数据。

## 2 设计约束

| 编号 | 约束 | 来源 | 对结构的影响 |
|---|---|---|---|
| C1 | 不得依赖 pip 安装第三方包 | 受限网络下无法稳定装包；课程允许灵活选型 | 全部用标准库：`http.server`、`sqlite3`、`urllib`、`json`；无 ORM、无框架 |
| C2 | 无 GPU，不做本地推理与训练 | 硬件条件 | 模型统一走 API；适配器保留本地模型接口位置 |
| C3 | 单用户、单机 | 首版范围 | 无认证层；不做会话隔离与并发写优化 |
| C4 | 前端不引入构建步骤 | 降低交付与排错成本 | 原生 JS + 全局函数；按 `app.js → agent.js → landing.js → keepalive.js` 顺序加载 |
| C5 | 数据与密钥不出本机 | 隐私与合规 | 资料落盘 `data/`，密钥存 `data/config.json`，该目录被 `.gitignore` 排除 |
| C6 | 中文检索 | 课程资料为中文 | 自实现分词（单字 + 二元）与 BM25，不依赖分词库 |

## 3 设计策略

| 策略 | 做法 | 理由 |
|---|---|---|
| 分层 | 界面层 / 接口层 / 领域层 / 存储层，依赖单向向下 | 便于替换存储或界面而不动业务 |
| 适配器隔离模型 | `deepseek.py` 暴露 `stream_chat` / `complete` / `chat_with_tools` | 换模型只改一个文件 |
| 证据先行 | 检索产出结构化证据，再由提示词拼装 | 引用可校验，避免模型自由发挥 |
| 工具化而非多页面 | 复杂操作交给工具，界面保持少量页面 | 减少页面数量与联调成本 |
| 流式优先 | 所有生成类接口走 SSE | 首字快，长回答体感好 |
| 可自检 | 内置 `check.py`（零成本）与 `selftest.py`（全链路） | 无测试框架也能回归 |
| 优雅降级 | 无 API 时 `--mock` 跑通界面；无证据时明说"资料里没有" | 演示与评审不依赖外部服务 |

## 4 系统总体结构

```
┌──────────────────────────────────────────────────────────────┐
│  浏览器（原生 JS 单页应用）                                    │
│  index.html · style.css                                       │
│  app.js（视图与业务） agent.js（指令框） landing.js（欢迎页/导航）│
│  keepalive.js（心跳与关页通知）                                │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP：JSON 请求 + SSE 响应
┌───────────────────────────▼──────────────────────────────────┐
│  接口层  server.py（ThreadingHTTPServer + Handler）            │
│  路由分发 · SSE 编码 · 上传下载 · 心跳与看门狗 · 静态资源        │
├──────────────────────────────────────────────────────────────┤
│  领域层                                                       │
│  rag.py      分词、BM25、科目路由、证据组装、引用校验           │
│  prompts.py  系统提示词与模板                                  │
│  tools.py    15 个工具的注册、校验与执行（含删除确认）           │
│  crawl.py    网页抓取与正文抽取（SSRF 防护、编码兜底）           │
│  seed.py     内置科目/章节、示例资料、目录重组                   │
├──────────────────────────────────────────────────────────────┤
│  适配层  deepseek.py（HTTP 客户端 + 流式解析 + mock 模式）      │
├──────────────────────────────────────────────────────────────┤
│  存储层  store.py（SQLite 访问、迁移、文件落盘）                │
│  数据：app/data/csla.db · materials/ · profile/ · config.json  │
└──────────────────────────────────────────────────────────────┘
```

**进程模型**：单进程、多线程（`ThreadingHTTPServer`）。SSE 连接各自占一个线程；SQLite 连接按需创建，写操作短事务。自动停服由后台线程按心跳状态判定。

**部署单元**：一个目录 + 一个 Python 解释器，无需安装。

## 5 子系统结构与功能

### 5.1 界面子系统

| 项 | 内容 |
|---|---|
| 职责 | 渲染 6 个视图（欢迎、首页、个人信息、聊天、总结、科目、资料）；处理交互与错误提示 |
| 组成 | `index.html`（结构与弹窗）、`style.css`（主题与动效）、`app.js`（视图与接口调用）、`agent.js`（两个自然语言指令框）、`landing.js`（粒子背景、导航栈、返回条）、`keepalive.js`（心跳） |
| 接口 | 调用 REST/SSE 接口；不直接访问数据库 |
| 关键约束 | 视图切换由 `switchView` 统一处理，主界面隐藏侧边栏；每个功能页注入"返回 / 主界面"条 |

### 5.2 接口子系统（`server.py`）

| 项 | 内容 |
|---|---|
| 职责 | 路由分发、参数校验、SSE 编码、文件上传下载、静态资源、心跳与自动停服 |
| 接口数量 | 19 组 REST 路径 + 2 个 SSE 流（`/api/chat/stream`、`/api/agent/stream`） |
| 关键实现 | `do_GET/do_POST/do_PATCH/do_DELETE` 统一入口；错误统一 `{"error": ...}`；SSE 事件 `delta` / `citations` / `completed` |
| 自动停服 | `/api/heartbeat` 更新最后活跃时间；`/api/client-closed` 记录关页；看门狗线程按可见/隐藏不同阈值退出 |

### 5.3 检索与生成子系统（`rag.py` + `prompts.py`）

| 项 | 内容 |
|---|---|
| 职责 | 中文分词、倒排统计、BM25 打分、按科目路由、证据预算控制、引用编号分配与校验 |
| 关键参数 | BM25 `k1=1.5`、`b=0.75`；标题加权 3.0；证据预算 3,600 字符；切片目标 480 字、重叠 80 字 |
| 拒绝策略 | 覆盖度不足或最高分低于阈值时返回"资料不足"，不生成无依据回答 |
| 输出 | 证据列表（含资料标题与片段）+ 引用编号表 |

### 5.4 工具子系统（`tools.py`）

| 项 | 内容 |
|---|---|
| 职责 | 注册 15 个工具；参数校验；权限（资料域/学习域）；执行并返回结构化结果 |
| 工具清单 | `list_folders`、`list_materials`、`move_material`、`classify_materials`、`create_folder`、`delete_material`、`import_url`、`search_materials`、`list_subjects`、`add_subject`、`delete_subject`、`add_chapter`、`update_chapter`、`delete_chapter`、`generate_questions` |
| 安全 | 删除类必须 `confirm=true`；`import_url` 限 http/https 且拒绝内网地址；单次抓取上限 2 MB |
| 与模型的关系 | `chat_with_tools` 循环：模型请求工具 → 程序执行 → 结果回填 → 继续生成，最多若干轮 |

### 5.5 采集子系统（`crawl.py`）

| 项 | 内容 |
|---|---|
| 职责 | 按白名单抓取课程网页，抽正文，切分入库 |
| 正文抽取 | 按标签栈丢弃 nav/sidebar/footer/toc；优先取 `article`/`main`；MathJax 取 `data-latex` 还原公式；TeX 符号转可读字符 |
| 编码 | 依次尝试 utf-8 / gb18030 / gbk / big5 |
| 兜底 | Python TLS 被站点掐断时改用系统 `curl` |
| 触发 | 仅 `--crawl` 显式执行，不隐式联网 |

### 5.6 适配子系统（`deepseek.py`）

| 项 | 内容 |
|---|---|
| 职责 | 封装 HTTP、鉴权、超时、重试与流式解析；提供 `validate` / `stream_chat` / `complete` / `chat_with_tools` |
| 模式 | 真实模式（`api.deepseek.com`）与 `mock` 模式（本地占位流，供无网演示与自检） |
| 约束 | 不写日志到磁盘；密钥仅从内存配置读取 |

### 5.7 存储子系统（`store.py`）

| 项 | 内容 |
|---|---|
| 职责 | 建表与迁移、CRUD、文件落盘、孤儿资料归置、统计 |
| 表 | `config`、`users`、`folders`、`materials`、`chunks`、`conversations`、`messages`、`summaries`、`mistakes`、`subjects`、`chapters`、`attempts`、`questions`（13 张） |
| 迁移方式 | 启动时检查列是否存在，缺列则 `ALTER TABLE` 追加，保证旧库可升级 |

## 8 关键设计决策与权衡

| 决策 | 备选 | 选择理由 | 代价 |
|---|---|---|---|
| 零第三方依赖 | Flask/FastAPI + 前端框架 | 受限网络无法稳定装包；交付即可跑 | 路由与 SSE 需手写；无 ORM |
| 词法检索 + BM25 | 向量检索（需 embeddings API） | DeepSeek 未提供 embeddings；中文语料上词法可解释 | 语义近似问题召回较弱 |
| 工具化改软件 | 为每个操作做页面 | 页面与联调成本高；指令更贴近用户表达 | 依赖模型判断，需二次确认兜底 |
| 单用户无登录 | 账号体系 | 首版范围为本地单机 | 无法多机同步 |
| 自动停服 | 常驻后台服务 | 避免用户忘记关进程 | 关页即停，刷新有宽限 |
