## 1 数据库环境说明

| 项 | 内容 |
|---|---|
| DBMS | SQLite 3（Python 标准库 `sqlite3` 内置） |
| 版本要求 | Python 3.10+ 携带的 SQLite（≥ 3.35） |
| 部署形态 | 单文件数据库，随程序目录存放，无独立服务进程 |
| 文件位置 | `AIassistant/app/data/csla.db` |
| 字符集 | UTF-8 |
| 事务 | 自动提交模式下按操作提交；批量写（导入资料）单事务 |
| 外键 | 连接时执行 `PRAGMA foreign_keys=ON` |
| 并发 | 单用户单进程，多线程读；写操作短事务，未启用 WAL |
| 备份 | 直接复制 `data/` 目录；程序内不提供备份按钮 |

## 2 数据库的命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 表名 | 小写、复数、下划线分隔 | `materials`、`chapters` |
| 字段名 | 小写、单数、下划线分隔 | `material_id`、`created_at` |
| 主键 | 统一 `id`，TEXT 存 UUID（`config` 表除外，用 `key`） | `id = "3f2a…"` |
| 外键 | `<主表单数>_id` | `chapter_id`、`conversation_id` |
| 时间字段 | 统一 `created_at`，TEXT 存 `YYYY-MM-DD HH:MM:SS` | `2026-10-24 21:49:26` |
| 排序字段 | `ord`，整数递增 | `ord = 3` |
| 布尔字段 | 整数 0/1，前缀 `is_` | `is_builtin`、`is_shared` |
| 索引 | `idx_<表>_<字段>` | `idx_chunks_material` |
| 枚举值 | 小写英文单词 | `kind = 'recent' / 'chapter' / 'tips'` |

## 3 逻辑设计

### 3.1 实体与关系

```
folders 1 ──── N materials 1 ──── N chunks
subjects 1 ──── N chapters 1 ──── N questions 1 ──── N attempts
conversations 1 ──── N messages
conversations 1 ──── N summaries（可为空，章节小结无会话）
users 1（单用户）─── 档案正文 + 四项基本信息
config（键值对，与其它表无关系）
mistakes（独立表，按科目/章节文本归档）
```

### 3.2 实体说明

| 实体 | 说明 | 主要关系 |
|---|---|---|
| config | 运行时配置键值对，含 API Key 与模型选择 | 无 |
| users | 唯一用户；姓名、档案正文、年龄/性别/专业/需求 | 无（单用户） |
| folders | 资料文件夹；核心资料 `is_shared=1`，`slug` 供程序识别 | 1:N materials |
| materials | 资料元数据：标题、科目、所属文件夹、来源 URL、磁盘路径、字节数 | N:1 folders；1:N chunks |
| chunks | 资料切片：序号 + 文本，检索的最小单元 | N:1 materials |
| conversations | 会话：类型、标题、创建与更新时间 | 1:N messages / 1:N summaries |
| messages | 消息：角色（user/assistant）、正文、引用编号 JSON | N:1 conversations |
| summaries | 总结：类型（对话/章节/易错本）、标题、正文 | N:1 conversations |
| mistakes | 错题：科目、章节、题干、我的答案、正确答案、备注 | 无外键（按文本归档） |
| subjects | 科目：名称、slug、排序、是否内置 | 1:N chapters |
| chapters | 章节：标题、排序、大纲、是否内置 | N:1 subjects；1:N questions |
| questions | 题目：题干、选项 JSON、答案、解析 | N:1 chapters；1:N attempts |
| attempts | 作答记录：答案、是否正确 | N:1 questions |

### 3.3 关键约束

| 约束 | 位置 | 说明 |
|---|---|---|
| 主键唯一 | 各表 `id` | UUID，避免自增冲突 |
| 外键级联 | `chunks.material_id`、`messages.conversation_id`、`chapters.subject_id`、`questions.chapter_id` | 删父表时子表记录随之处理 |
| 内置保护 | `subjects.is_builtin`、`chapters.is_builtin` | 应用层禁止删除，接口返回 409 |
| 核心资料保护 | `folders.is_shared` | 应用层禁止删除该文件夹 |
| 单用户唯一行 | `users` | 启动时 `ensure_user()` 保证只有一行 |

## 5 安全性设计

### 5.1 防止用户直接操作数据库的方法

| 措施 | 说明 |
|---|---|
| 单一访问入口 | 所有读写经 `store.py`，界面与模型都不能直接执行 SQL |
| 参数化语句 | 全部使用 `?` 占位符，不拼接字符串，杜绝注入 |
| 工具白名单 | 模型只能调用 15 个已注册工具，无"执行 SQL"类工具 |
| 危险操作确认 | 删除资料/科目/章节的工具必须 `confirm=true` |
| 库文件不外传 | `app/data/` 被 `.gitignore` 排除，不进版本库 |

### 5.2 用户帐号密码的加密方法

本系统**首版无账号与密码**，因此不存在口令存储。需说明的两项敏感数据：

| 数据 | 存放 | 保护方式 |
|---|---|---|
| DeepSeek API Key | `data/config.json`（明文） | 仅本机可读；界面只显示掩码（如 `sk-acc…ec12`）；不写日志、不回显完整值 |
| 会话与资料 | 同一 `data/` 目录 | 依赖操作系统文件权限；不做应用层加密 |

> 明文存储是本机单用户场景下的取舍，风险与改进方向已登记在 8.2 未实现项。

### 5.3 角色与权限

| 角色 | 数据库层面 | 应用层 |
|---|---|---|
| 使用者 | 通过接口读写本人全部数据 | 可删自定义科目/章节/资料；不可删内置项与核心资料夹 |
| 模型（工具调用） | 无直连权限，只能经工具 | 删除类需显式确认；抓取限 http/https 且拒内网 |
| 指导教师 | 只读查看代码与文档 | 不接触运行数据库 |

## 6 优化

| 措施 | 现状与说明 |
|---|---|
| 索引 | 已建 2 个：`idx_chunks_material`、`idx_messages_conv`；其余表数据量小，依赖主键索引 |
| 检索 | 不做 SQL 全文检索，启动时把 `chunks` 读入内存构建倒排（`Retriever`），检索在内存完成 |
| 批量写 | 导入资料时单事务写入元数据与全部切片，避免逐条提交 |
| 分页 | 消息与资料列表一次取全量（单用户量级可接受）；未实现分页 |
| 未采用 | 未启用 WAL、未做连接池、未做查询计划分析——单用户场景收益有限 |
| 未来 | 资料量超过 5,000 切片时考虑增量索引与 WAL |

## 7 数据库管理与维护说明

| 项 | 做法 |
|---|---|
| 初始化 | 首次启动自动建表；`seed.py` 写入内置四科 19 章与示例资料 |
| 升级 | 启动时按列存在性做 `ALTER TABLE` 追加，兼容旧库（v0.3 已为 `users` 增四列） |
| 重建索引 | `python reindex.py`：清空并重建全部切片；资料文件不动 |
| 清理 | 删除资料时连带删除 `chunks` 与磁盘文件；孤儿资料由 `assign_orphan_materials()` 归入根目录 |
| 备份 | 复制 `app/data/` 目录即可；恢复时覆盖回去 |
| 排障 | `python check.py` 检查数据健康（重复资料、过小资料、核心文件夹数量） |
| 容量 | 单库 < 50 MB 视为正常；超过时优先检查是否误导入大文件 |
