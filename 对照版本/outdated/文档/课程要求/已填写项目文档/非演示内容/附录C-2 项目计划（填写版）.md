## 0. 文档介绍


### 0.1 文档目的

本文档用于组织三人小组在八周内完成「计算机课程学习助手」项目的范围定义、资源安排、进度控制与变更管理，并由机构领导据此审批。本计划描述“谁、在什么时候、用什么资源、交出哪些可验收的成果”，产品功能细节见《产品需求规格说明书》（G-2），技术方案见体系结构设计报告（I-1）。

## 1. 项目介绍


### 1.1 项目范围

（1）是什么：一个在个人电脑本地运行的 AI 学习助手。学生填入自己的 DeepSeek API Key 后进入系统，导入课程资料即可获得带引用编号的问答；按科目与章节学习、做题、看小结；并能用一句自然语言让 AI 整理资料、增删章节。资料与数据全部保存在本机目录，模型能力通过 DeepSeek API 获取。
（2）应当包含的内容：
　1) 资料管理：核心资料（core）与四学科文件夹，导入、切片建索引、点击打开源文件、删除资料与文件夹；
　2) 资料问答：检索 → 组装证据 → 流式生成 → 服务端校验引用编号是否合法；
　3) 科目学习：计算机组成原理、计算机网络、操作系统、数据结构四门课共 19 章，含大纲、讲解、单选练习、判分、错题、章节小结、推荐学习视频；
　4) 工具化 AI：15 个工具（资料增删移、按科目归类、抓取网页、科目与章节增删改、出题），删除类操作强制二次确认；
　5) 个人信息：年龄、性别、专业、需求四栏目，按月学习者档案，易错提示本；
　6) 交付件：可运行代码、九份项目文档、每日修改日志、启动脚本与安装说明。
（3）不包含的内容：登录注册与账号体系；本地大模型推理；模型微调训练；原生移动 App；OCR 与多模态；开放题自动批改；代码执行沙箱；多用户高并发；自动全网爬取资料。
（4）适用的领域：计算机专业本科课程的课后自学与练习，以本地资料为依据的问答。
（5）不适用的领域：需要权威答疑的正式教学场景、任何替代教材的场景、计算机以外学科。
（6）关于平行版本：另一 AI 产出的实现（AIassistant2/）在仓库 gpt-version 分支并行维护，作为技术路线对照，不计入本计划的 WBS 与工作量。

### 1.3 客户与最终用户介绍

本项目为课程项目，非合同项目。
客户与验收方：课程指导教师。验收依据课程安排与九份交付文档。
最终用户特征：计算机专业本科生，已在学相关课程，有至少一门专业课的电子资料，愿意自行申请并填写 API Key，以 Windows 笔记本为主要使用环境；典型场景是期末复习与课后补漏，单次使用 20–60 分钟。
需求来源：课程文档与教师要求、本项目自测与内部评审。尚未开展独立的用户访谈或问卷，涉及真实使用习惯的判断均为假设，需在第 2 周前确认。

## 2. 项目过程定义


### 2.1 过程模型

裁剪 SPP 模型，采用每周一轮的小步迭代。每轮固定五个动作，并以下一轮的需求细化收尾：
需求细化 → 设计（含接口与数据） → 实现 → 自测 → 文档与评审 → 下周计划
第 1 周：范围冻结、技术选型验证、资料清单与采集。
第 2–4 周：核心链路（检索、问答、科目学习）逐条打通。
第 5–6 周：工具化 AI、界面与动效、个人信息。
第 7–8 周：测试、安装验证、九份文档与答辩材料。
第 6 周末功能冻结，此后只做缺陷修复与文档，不新增功能。每周必须产出一个可运行、可演示的片段，避免最后一周集中联调。

### 2.2 方法与工具

| 过程域 | 方法与工具 |
|---|---|
| 需求与设计 | Markdown 文档；用例与接口用文字加表格描述；接口契约用 JSON |
| 版本控制 | Git + GitHub（SSH 协议）；main 为本体，gpt-version 为平行版本 |
| 实现 | Python 3.10+ 标准库（http.server、sqlite3、urllib）；前端原生 JS，无构建步骤 |
| 数据 | SQLite 单文件数据库；资料与档案按文件落盘 |
| 模型接入 | DeepSeek chat/completions，流式 SSE 与 function calling |
| 测试 | 自研 check.py（20 项，零成本）与 selftest.py（44 项，全链路） |
| 文档 | Markdown 为主，交付件用 python-docx 生成 Word |
| 协作 | 每周例会加周报；PR 评审；每日自动生成修改日志 |

选型原则：只采用实际会用到的工具，不为展示而引入框架。因此未采用 Vue、Flask、向量数据库等方案，理由与验证记录见附录C 的 CHG-003。
