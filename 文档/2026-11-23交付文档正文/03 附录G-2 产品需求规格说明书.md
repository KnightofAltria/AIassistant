1. 产品介绍

本产品是面向计算机课程的本地学习助手。

学生登录后导入课程资料，进行带出处问答、章节练习、错题复习和学习总结。资料、记录按账号保存在本机；生成服务调用 DeepSeek API。

以复习 TCP 重传为例，先导入课件，再到科目学习打开对应章节，生成大纲和小节讲解，点击出处对照原文，完成练习并复习错题，最后在看板确认阅读和复习进度。

2. 产品面向的用户群体

主要服务于计算机相关专业学生及课程项目评审人员。

桌面学生用本地账号进入自己的学习库。桌面管理员维护账号及本人核心资料。安卓以手机本地用户运行。

预期收益是减少资料查找与重复整理，集中查看练习结果；未开展正式用户调研，不估计采用率。

3. 产品应当遵循的标准或规范

遵循课程模板及项目提交约定。接口采用 HTTP/JSON，流式事件采用 SSE；数据库操作使用参数化 SQL。资料导入须有使用权限，模型回答需提示出处与证据不足，不替代教师结论。

4. 产品范围

支持资料导入、审核、引用、开放教材目录、分节讲解、练习与复习、看板及报告导出。扫描 PDF 需要可提取文字。Windows 10 22H2/11 x64、Apple Silicon macOS 12+ 为桌面包的目标环境，安卓目标为 Android 8.0+（arm64-v8a/x86_64，WebView 100+）。设备兼容性以实机验收为准。

5. 产品中的角色

安卓 0.2.0 采用手机本地用户，Kotlin 和 WebView 承载界面，Chaquopy 运行内置 Python。使用已有内容可离线，DeepSeek 生成和教材下载需联网。

| 角色名称 | 职责描述 |
| --- | --- |
| 学生 | 管理本人资料、对话、作答、档案；核心资料只读。 |
| 管理员 | 管理账号启停、密码重置；可修改本人核心资料。 |
| 手机本地用户 | 维护手机资料和学习记录，通过系统选取、保存和分享文件。 |
| 指导教师／评审人 | 审阅需求、演示和测试记录，不预设系统管理权限。 |

6. 产品的功能性需求

6.0 功能性需求分类

按账号、资料、学习三个类别组织需求，以下标识用于设计和测试追踪。

| 功能类别 | 功能名称、标识符 | 描述 |
| --- | --- | --- |
| 个人信息 | FR-01 / FR-02 登录与权限 | 桌面按账号隔离，安卓进入手机本地用户。 |
| 个人信息 | FR-03 / FR-04 头像与记录 | 头像可裁剪，清理本人记录前确认范围。 |
| 资料服务 | FR-05 / FR-06 导入与引用 | 导入文档，维护参考目录和章节映射，打开引用原文。 |
| 资料服务 | FR-07 / FR-08 教材与资料管理 | 搜索开放教材，管理文件夹及原始资料。 |
| 学习辅助 | FR-09 / FR-10 聊天与分节学习 | 检索证据后流式问答，大纲与小节可独立生成并保存。 |
| 学习辅助 | FR-11 / FR-12 练习与看板 | 按讲义出题、解析、错题复习及导出学习报告。 |

6.m 学习辅助功能

以下是核心流程需求。聊天和讲义需分别验证出处。断网或缺少 Key 时提供可继续阅读的路径。

6.m.n 学习流程 FR-01 至 FR-12

| 名称、标识符 | 学习闭环 FR-01～FR-12 |
| --- | --- |
| 功能描述 | 导入资料到课程，学习、练习、复习并查看记录。 |
| 优先级 | 核心：资料、引用、讲义、练习与数据保护。 |
| 输入 | 可解析文档、问题、章节、题量及作答。 |
| 操作序列 | 选择资料 → 读大纲与讲义 → 核对出处 → 作答 → 复习。 |
| 输出 | 可保存讲义、解析、复习状态、看板与报告。 |
| 补充说明 | 小节重生成时保留已有题并提示内容可能不同。 |

用独立测试库核对引用、作答、讲义保存和权限，分别登记真实模型、替代响应与设备验收。

7. 产品的非功能性需求

7.1 用户界面需求

| 需求名称 | 详细要求 |
| --- | --- |
| 一致性 | 保留蓝白界面、SVG 图标、卡片首页与粒子欢迎页；导航和按钮语义一致。 |
| 状态反馈 | 区分账号登录、模型 Key 校验、加载、成功、失败与空状态；提交中禁用重复操作。 |
| 可操作性 | 阅读页支持刷新和前进后退；危险操作明确确认；窄屏内容不溢出。 |

7.2 软硬件环境需求

| 需求名称 | 详细要求 |
| --- | --- |
| 运行环境 | Windows 10 22H2/11 x64、Apple Silicon macOS 12+ 为桌面包的目标环境，安卓目标为 Android 8.0+（arm64-v8a/x86_64，WebView 100+）。设备兼容性以实机验收为准。 |
| 网络与端口 | 本机服务仅用平台约定的回环地址。模型与在线资源需联网。 |
| 存储 | 本机可写目录；容量随资料增长。硬件最低资源未通过容量测试确定。 |

7.3 产品质量需求

| 主要质量属性 | 详细要求 |
| --- | --- |
| 正确性 | 按需求标识验证成功与失败场景，生成内容不保证事实完全正确。 |
| 健壮性 | 拒绝空输入、超限文件、非法参数和越权访问，说明恢复方式。 |
| 可靠性 | 关键写操作使用事务；删除与源文件清理一致，断连不使服务崩溃。 |
| 性能，效率 | 流式反馈减少等待；采用检索与回答缓存。吞吐量及响应时限尚未正式量测。 |
| 易用性 | 统一导航、空状态和确认提示；首次使用区分账号密码与 API Key。 |
| 清晰性 | 模块、接口及错误信息可追踪，文档对应当前源码。 |
| 安全性 | 密码哈希存储、角色和目录隔离；公网部署另需 HTTPS，禁止暴露密钥。 |
| 可扩展性 | 新增资料类型、模型或学习功能通过对应模块扩展，不更改既有数据含义。 |
| 兼容性 | 现代浏览器为目标；复杂 Word/PDF 版式和浏览器兼容性须实际验收。 |
| 可移植性 | 后端以标准库实现；Windows 启动脚本及本机打开功能需平台适配。 |
| 数据与验收 | 数据范围：核心资料非跨账号同步库；正式模型质量与用户验收待完成。 |

7.n 其它需求

运维要求：运行数据、密钥和会话不得提交 Git；目录改名或切换副本前应停止旧服务，避免 8737/8740 端口复用造成连接到错误账号库。

附录A：需求建模与分析报告

以角色用例和资料状态转换描述需求，不依赖特定建模软件。

A.1 需求模型1

以复习 TCP 重传为例，先导入课件，再到科目学习打开对应章节，生成大纲和小节讲解，点击出处对照原文，完成练习并复习错题，最后在看板确认阅读和复习进度。

A.n 资料与权限状态模型

资料状态：导入 → 待审核或可用；待审核 → 审核通过 → 加入检索；编辑、移动、删除或审核变化 → 索引版本递增 → 缓存失效。权限条件：本人普通资料可写，学生核心资料只读；管理员可写本人核心资料。删除需确认，清除记录不得影响资料和其他账号。
