1. 测试范围与主要内容

本计划覆盖 应用的学习流程、安卓本地版和桌面封装。Windows 10 22H2/11 x64、Apple Silicon macOS 12+ 为桌面包的目标环境，安卓目标为 Android 8.0+（arm64-v8a/x86_64，WebView 100+）。设备兼容性以实机验收为准。

确认核心学习流程能够完成，数据可重读、来源可核对、平台权限正确，并汇总环境尚未覆盖的项目。

1.1 测试范围

测试类别：功能测试；主要内容：账号注册/登录/退出/改密/设备管理/注销；资料导入、编辑、移动、删除、审核；问答与引用；大纲与讲义；练习判分、错题、复习；看板、总结、档案、设置；管理员权限；是否包含：包含

测试类别：健壮性测试；主要内容：空值与超长输入、损坏文件、扫描版 PDF、认证/模型不可用、重复提交、并发写入；是否包含：包含

测试类别：性能测试；主要内容：首页与主要接口响应、文本导入与索引、本地检索、单章讲义生成；是否包含：包含（本机抽测）

测试类别：界面测试；主要内容：桌面、窄屏、横屏布局；键盘操作；空状态与错误提示；是否包含：包含

测试类别：安全性测试；主要内容：密码存储、会话 Cookie、未登录访问、越权、SQL 注入、路径穿越、登录限流、XSS；是否包含：包含（非专业渗透）

安装/卸载：Windows 完整解压与启动，macOS DMG 安装，安卓同签名覆盖与本地数据保留。

压力：用临时实例记录本机连续操作及失败原因，性能指标按设备标注。

可靠性：生成中断、应用重启、手机后台取消及状态恢复。

测试类别：不包含；主要内容：公网高并发与容量规划、专业渗透测试与代码审计、全平台/全浏览器兼容矩阵、模型回答事实正确性的全面评测、长期 SLA；是否包含：不包含

1.2 测试重点

• 引用可追溯：回答中的 [cN] 编号必须能在来源列表打开，且来源属于当前科目；

• 账号与数据隔离：A、B 两个账号的资料、对话、练习、档案互不可见；

• 权限边界：学生不能修改核心资料，普通用户不能调用管理员接口；

• 导入解析：PDF 页码、Word/Markdown 标题、损坏文件与扫描件的处理；

中断后已有小节仍可阅读。未完成生成不覆盖旧内容。

阅读、小题和错题复习状态分别更新，未满足条件时掌握度不得显示为完全掌握。

1.3 需求覆盖说明

以 K-2 中各测试域及 应用新增的测试场景追踪需求。旧版用例可用于回归，历史通过记录属于 早期版本。

2. 测试方法

2.1 黑盒场景测试

以复习 TCP 重传为例，先导入课件，再到科目学习打开对应章节，生成大纲和小节讲解，点击出处对照原文，完成练习并复习错题，最后在看板确认阅读和复习进度。

2.2 接口与自动化测试

自动化使用 check.py、应用共享 回归、安卓后端和手机网页测试，使用独立临时库与模型替代响应。

2.3 边界与异常测试

对输入长度、空值、重复提交、损坏文件、依赖服务不可用等采用等价类划分、边界值与错误推测；对并发的写操作做重复执行，观察是否出现锁等待、重复记录或数据错乱。

2.4 判定依据

功能是否通过以页面可观察结果、接口返回码与数据库记录为准；模型回答只评价“是否给出引用、是否说明资料不足”，不以模型自评分替代人工判断。界面以桌面、窄屏、横屏三种窗口宽度的人工检查为准。

2.5 缺陷复现

发现缺陷后先固定版本与数据状态，记录最小复现步骤；修复后在相同步骤上回归，并补一条自动化或手工用例，避免同类问题再次出现。

4. 测试完成准则

4.1 用例准则

逐项记录通过、失败、跳过及未执行。运行环境缺少时保留原因和下一步，实际结果汇总到 K-3。

4.2 缺陷准则

阻断级与严重级缺陷必须修复并回归通过；一般级缺陷允许遗留，但需登记影响范围与规避方式；轻微问题可进入后续版本。涉及数据泄露、越权、错误计分、审核绕过的问题一律按严重处理。

4.3 性能准则

记录资料大小、设备、冷启动和生成起止时间。在线生成含网络和模型耗时，单独记录。

4.4 退出准则

提交验收时应给出核心用例、当期回归证据和遗留问题清单，Windows、安卓原生及真实模型结果按环境分别登记。

6. 缺陷管理与改错计划

6.1 管理流程

缺陷流程为：新建 → 确认 → 修复 → 回归 → 关闭；回归不通过则重开。每条缺陷记录编号、关联用例、发现版本、复现步骤、预期/实际、证据（截图或日志）、严重程度、负责人、修复提交与回归人。当前使用文档表格管理，并与 Git 提交信息关联，暂不引入专用缺陷管理平台。

6.2 缺陷等级

等级：阻断；定义：服务无法启动、登录完全不可用、数据无法读取；处理要求：立即修复，修复前停止相关测试

等级：严重；定义：越权访问、数据账号数据混用、错误计分、审核绕过、数据丢失；处理要求：当日修复并回归

等级：一般；定义：主要功能可用但结果不正确或交互受阻，有规避方式；处理要求：本轮修复或登记遗留

等级：轻微；定义：文案、样式、非关键提示问题；处理要求：可进入后续版本

6.3 回归策略

修复后先执行对应的自动化脚本，再按原步骤手工回归；涉及认证、数据库或索引的修改，追加运行 test_auth.py 与 check.py 全量。每次回归记录版本号与执行人，避免“修好又复发”无法追踪。

7. 进度安排与风险

阶段：先复用 早期版本用例作为回归基线，再列 应用各端的新增用例。

阶段：11月21日，安卓临时库和共享回归、模拟手机网页与 APK 构建检查。

阶段：11月22日，macOS 真实 WKWebView 检查，Windows 交叉构建与软件包检查。

阶段：按真机设备可用情况补 Windows、安卓原生以及真实模型验收。

7.1 风险与应对

风险：缺少 Windows 或安卓实机时，保留构建和模拟证据，实机条目单列。

风险：模型输出不稳定；影响：讲义与问答质量波动；应对：使用固定问题集与人工抽查；不把模型自评当结论

风险：扫描版 PDF 无文字层；影响：目录提取失败；应对：提示需 OCR；允许手工填写目录，不生成错误页码

风险：时间紧、功能仍在迭代；影响：用例无法全部执行完；应对：优先核心流程与权限；未执行项如实登记
