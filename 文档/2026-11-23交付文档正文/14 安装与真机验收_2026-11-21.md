在手机直接安装

1. 将 APK 传到手机，打开文件并允许当前文件管理器安装应用。

2. 已有同签名 0.1.1 时可覆盖安装；第一次运行进入首页，之后恢复上次页面与输入草稿。

3. 首先在离线状态阅读内置资料，创建一个测试科目与手工章节，确认目录、返回和资料页可用。

4. 需要生成时，进入“设置”填写自己的 DeepSeek API Key，保存并校验；再选择一节讲义生成。

手机内自行启动 Python 学习服务，使用时无需电脑启动服务或设置端口反向代理。

连接 Mac 调试

1. 手机“关于手机”连续点击版本号开启开发者选项，然后打开“USB 调试”。

2. 用数据线连接并在手机确认 USB 调试。Android Studio 打开源码根目录的 android 工程。

3. 终端使用已安装的 Platform-Tools，确认设备列表为 device，再覆盖安装。

确认 adb 位于终端 PATH 中，然后执行：

adb devices -l

adb install -r "CSLA-安卓调试版-0.2.0.apk"

adb shell am start -n cn.csla.mobile/.MainActivity

多台设备时在命令中添加 -s 设备序列号。若显示 unauthorized，在手机确认授权；没有弹窗时重新插拔，必要时撤销 USB 调试授权后重连。显示 offline 时重连并重启 adb server；列表为空时先检查线材、手机连接方式及 USB 调试开关。

打开 Mac Chrome 的 chrome://inspect/#devices，可检查本调试包的 WebView、Console 和页面请求。release 构建关闭此能力。

查看进程日志：

adb shell pidof cn.csla.mobile

adb logcat --pid=<上一条返回的PID>

在终端中把 PID 占位符替换为实际数字后执行。进程退出后可用 Android Studio Logcat 选择 cn.csla.mobile 查看崩溃前日志。进一步 USB/无线调试步骤见仓库“文档/手机端移植/安卓手机连接与调试指南_2026-11-21”。

常见情况

覆盖安装显示 INSTALL_FAILED_UPDATE_INCOMPATIBLE 通常说明签名不同；应使用原签名重新构建。不要为绕过错误直接卸载，卸载会删除本地学习库。当前交付包已核对与本地此前 0.1.1 的签名一致，但不同电脑生成的调试签名可能不同。

INSTALL_FAILED_VERSION_DOWNGRADE 表示手机已安装更高 versionCode，应使用更高版本构建；本包 versionCode 为 3。缺少对应 ABI 或系统低于 Android 8.0 时，需要符合要求的设备。

生成失败时先检查网络、Key 校验与服务提示。离线时仍可阅读已有内容。扫描 PDF 没有可提取文字时不会新增 OCR 功能，需要文本版或先自行 OCR。
