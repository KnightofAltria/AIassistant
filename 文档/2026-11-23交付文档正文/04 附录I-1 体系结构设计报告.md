1. 系统概述

网页、桌面和手机应用共享 学习界面与业务能力。关键路径包括资料解析、检索引用、模型生成、章节分节保存和学习记录统计。

2. 设计约束

主要设计约束如下。

范围：课程作业与本机演示优先，不以生产级多租户服务作为已实现目标。

协议：浏览器与业务服务通过 HTTP/JSON 与 SSE 交互；认证通过独立 HTTP 接口，真实模型走外部 HTTPS API。

Windows 10 22H2/11 x64、Apple Silicon macOS 12+ 为桌面包的目标环境，安卓目标为 Android 8.0+（arm64-v8a/x86_64，WebView 100+）。设备兼容性以实机验收为准。

源码网页默认 8737/8740。桌面封装内置本机学习与账号服务。安卓仅监听本机回环，用会话凭据限制访问。

安卓 0.2.0 采用手机本地用户，Kotlin 和 WebView 承载界面，Chaquopy 运行内置 Python。使用已有内容可离线，DeepSeek 生成和教材下载需联网。

质量：拒绝未授权核心资料操作，待审核资料不参与检索；缓存须随索引版本、配置及用户上下文失效。

依赖：用户具备资料使用权限并自行提供 Key。外部服务可能限流、断连或返回不可靠内容；PDF 文字提取不包含 OCR。

3. 设计策略

采用浏览器表现层、业务编排层、领域与存储模块的职责分离。

PDF、DOCX 和文本处理进入解析与索引层，章节教材目录与映射负责缩小证据范围，业务路由将证据传入生成层。

复用：对话、章节辅导和复习共用模型客户端；资料切片及检索结果共用于引用生成；工具调用复用存储及权限规则。

折衷：标准库与 SQLite 降低安装成本，BM25 不依赖向量服务；代价是语义召回和高并发能力有限，需用真实课程问题评估。

4. 系统总体结构

部署关系：浏览器 → 本机业务与认证；桌面 WebView/WKWebView → 内置服务；安卓原生壳 → 手机 Python 服务。三者分别写入自身本地目录，并按需访问 DeepSeek。

逻辑结构：界面 → HTTP/SSE 路由 → 账号校验与用户目录绑定 → 资料/学习/模型模块 → SQLite 与文件。认证库独立于学习库，避免混合密码和学习内容。

拆分理由：认证可独立配置，学习数据留在本机；检索、解析与模型模块可分别测试；前端只通过受控接口访问数据。

导入原件 → 提取正文、目录和片段 → 索引；提出问题或选择小节 → 检索证据 → 流式生成、校验引用 → 保存会话或完整小节。

5. 子系统N的结构与功能

子系统按职责划分如下。

表现层：界面使用原生 JavaScript 绘制侧栏、讲义与看板。安卓 mobile.js/mobile.css 提供窄屏及桥接交互，桌面容器提供系统文件保存。

业务子系统：server.py 编排 HTTP/SSE；store.py 管理用户数据；rag.py 完成切片检索；deepseek.py 与 prompts.py 封装生成；tools.py 封装工具；extras.py/pdftext.py 提供扩展和文件解析。

认证与数据：桌面账号和学习数据分库，按用户隔离。手机以本地用户运行，密钥由 Android Keystore 支持加密保存。
