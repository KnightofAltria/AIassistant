## 1. 总体结构

```text
用户电脑                                         开发者电脑（或云服务器）
┌──────────────────────────────┐               ┌──────────────────────────┐
│ 浏览器  ──同源──▶  app/server.py ─────────────▶│ auth_server/auth_server.py│
│ （只拿到登录状态，│  本机服务     HTTP(S) /auth/* │  账号认证服务（8740）     │
│  拿不到 token）   │  保存 token                 │         │                │
│                  │  按用户分目录存学习数据       │   auth_server/data/auth.db │
└──────────────────────────────┘               └──────────────────────────┘
        │
        └─▶ DeepSeek API（用户自己的 Key，按账号保存在本机）
```

- **认证服务**只管账号、密码哈希、登录会话。不接触聊天、资料、模型请求。
- **本机服务**（现有的 `server.py`）代替浏览器和认证服务通信，持有 token；浏览器只调用本机 `/api/auth/*`。
- **学习数据**全部留在用户电脑，按账号分目录。

两者都只用 Python 标准库，与项目现有约束一致。

## 3. 账号字段规则

| 字段 | 规则 | 说明 |
|---|---|---|
| 用户名 | 3–20 位，仅字母、数字、下划线 | 不区分大小写判重（`Alice` 与 `alice` 视为同一账号）；保存时保留原始大小写用于显示 |
| 密码 | 8–64 位，至少含 1 个字母和 1 个数字 | 不限制特殊字符；前后空格视为密码的一部分，不做 trim |
| 昵称 | 可选，0–20 字，去掉首尾空格 | 为空时显示用户名 |
| 用户 ID | 服务端生成的 UUID4 | 稳定不变，本机数据目录以它命名 |

浏览器做同样的格式检查以便即时提示，**以服务端检查为准**。

### 账号表 `users`

| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT 主键 | UUID4 |
| username | TEXT | 原始大小写 |
| username_key | TEXT UNIQUE | 小写，用于判重和登录 |
| nickname | TEXT | |
| password_hash | TEXT | 见下 |
| status | TEXT | `active` / `disabled` |
| created_at / updated_at / last_login_at | TEXT | 本地时间 `YYYY-MM-DD HH:MM:SS` |

### 密码哈希

`pbkdf2_sha256$<迭代次数>$<盐 base64>$<哈希 base64>`

- 算法 PBKDF2-HMAC-SHA256，迭代 200,000 次，16 字节随机盐，32 字节输出。
- 迭代次数写在哈希串里，将来调高后旧哈希仍能校验。
- 比较用 `hmac.compare_digest`，防计时攻击。
- 不用 `hashlib.scrypt`：macOS 自带的 Python（LibreSSL）没有它，PBKDF2 在所有平台都可用。
- 用户名不存在时也对一个假哈希做一次校验，使“用户不存在”和“密码错误”耗时接近。

## 4. 会话与凭证

| 项 | 规定 |
|---|---|
| 凭证格式 | `secrets.token_urlsafe(32)` 生成的不透明随机串，不用 JWT |
| 服务端存储 | 只存 token 的 SHA-256，数据库泄露也拿不到可用 token |
| access token | 有效期 2 小时，放在 `Authorization: Bearer <token>` |
| refresh token | 有效期 30 天，只用于 `/auth/refresh` |
| 刷新 | 每次刷新**轮换**：旧会话作废，签发新的一对；旧 refresh token 再用会失败 |
| 多设备 | 允许同一账号多处同时登录，每处一个独立会话 |
| 撤销 | 退出登录撤销当前会话；改密码撤销该账号其他所有会话；禁用账号撤销全部会话；用户可在“登录设备”里让单台或其他所有设备下线 |
| 注销 | 本人输入密码注销：删除账号和全部会话，用户名可被重新注册 |

### 会话表 `sessions`

`id, user_id, access_hash, refresh_hash, access_expires, refresh_expires, created_at, revoked(0/1), user_agent, ip, device, login_at, last_seen`

- `device`：本机服务登录时上报的设备名（`主机名 · Windows/macOS/Linux`，≤ 60 字），为空时列表里显示“未命名设备”。
- `login_at`：首次登录时间，刷新轮换时沿用；`last_seen`：最近一次 `/auth/me` 的时间。
- 老库启动时自动补这三列。

### 频率限制（内存计数，服务重启清零）

| 场景 | 限制 | 超限返回 |
|---|---|---|
| 登录失败 | 同一用户名 15 分钟内 5 次；同一 IP 15 分钟内 20 次 | 429 `rate_limited` |
| 注册 | 同一 IP 1 小时内 10 次 | 429 `rate_limited` |
| 注销时密码错误 | 与登录共用“同一用户名 15 分钟内 5 次”的计数 | 429 `rate_limited` |

登录成功会清零该用户名的失败计数。

## 5. 认证服务接口

基础地址默认 `http://127.0.0.1:8740`。请求和响应都是 JSON（UTF-8），请求体上限 16 KB。

错误统一格式：

```json
{"error": {"code": "invalid_credentials", "message": "用户名或密码错误"}}
```

| 错误码 | HTTP | 含义 |
|---|---|---|
| `invalid_input` | 400 | 字段缺失或格式不符（message 指出哪一项） |
| `username_taken` | 409 | 用户名已被注册 |
| `invalid_credentials` | 401 | 用户名或密码错误（不区分是哪一个错） |
| `account_disabled` | 403 | 账号已被禁用 |
| `token_invalid` | 401 | token 不存在、已过期或已撤销 |
| `rate_limited` | 429 | 尝试过于频繁 |
| `not_found` | 404 | 接口不存在 |
| `server_error` | 500 | 服务内部错误 |

公共的 `user` 对象：`{"id", "username", "nickname", "status", "created_at"}`，**永不返回密码哈希**。

公共的 `tokens` 对象：`{"access_token", "access_expires_at", "refresh_token", "refresh_expires_at"}`，时间为 Unix 秒。

| 接口 | 请求 | 成功响应 |
|---|---|---|
| `POST /auth/register` | `{username, password, nickname?}` | 201 `{user}` |
| `POST /auth/login` | `{username, password, device?}` | 200 `{user, tokens}` |
| `GET /auth/me` | 头 `Authorization: Bearer <access>` | 200 `{user}` |
| `POST /auth/refresh` | `{refresh_token}` | 200 `{user, tokens}`（新的一对） |
| `POST /auth/logout` | 头 `Authorization: Bearer <access>` | 200 `{ok: true}`（重复退出也返回 200） |
| `POST /auth/password` | 头 + `{old_password, new_password}` | 200 `{ok: true}`，其他会话被撤销 |
| `POST /auth/profile` | 头 + `{nickname}`（1–20 字） | 200 `{user}`；用于改显示名 |
| `GET /auth/sessions` | 头 | 200 `{sessions: [{id, device, ip, login_at, last_seen, current}]}`，当前会话排第一 |
| `POST /auth/sessions/revoke` | 头 + `{others: true}` 或 `{session_id}` | 200 `{ok, revoked}`；指定当前会话 400 `invalid_input`，会话不存在 404 `not_found` |
| `POST /auth/delete` | 头 + `{password}` | 200 `{ok, user_id}`；密码错误 401 `invalid_credentials`，超限 429 |
| `GET /auth/health` | 无 | 200 `{ok: true, time}` |

注册成功**不自动登录**，由客户端紧接着调用一次登录（界面上表现为“注册并进入”）。

## 6. 本机学习助手的改动

### 6.1 认证服务地址

优先级：启动参数 `--auth-server URL` > 环境变量 `CSLA_AUTH_SERVER` > `app/data/client.json` 的 `auth_server` > 默认 `http://127.0.0.1:8740`。

### 6.2 浏览器 ↔ 本机服务

浏览器不直接访问认证服务（避免跨域、避免 token 暴露在页面脚本里），只调本机代理接口：

| 本机接口 | 作用 |
|---|---|
| `GET /api/auth/status` | `{logged_in, user, offline, auth_server, auth_required}` |
| `POST /api/auth/register` | 转发注册，成功后自动登录 |
| `POST /api/auth/login` | 转发登录，保存会话，切换到该用户数据 |
| `POST /api/auth/logout` | 通知认证服务撤销会话（失败也继续），清除本机会话 |
| `POST /api/auth/password` | 转发改密 |
| `GET /api/auth/sessions` | 登录设备列表；`--no-auth` 时 400，认证服务不可达 503 |
| `POST /api/auth/sessions/revoke` | 转发“下线”（单台或其他所有设备） |
| `POST /api/auth/delete` | `{password}`。认证服务注销成功后：关闭本机数据库连接 → 删除 `app/data/users/<用户ID>/` → 清除本机会话，返回最新登录状态 |

改密、下线、注销这三个接口如果发现当前会话已失效（`token_invalid` / `account_disabled`），本机会清除会话并返回 401 `auth_required`，前端回到登录页。

浏览器端只在 `localStorage` 里记“记住的用户名”（勾选“记住用户名”时），不保存密码；注销账号时如果记的是这个用户名，一并清除。

会话保存在 `app/data/session.json`（文件权限 0600），内容为 tokens、用户信息、`last_verified`（上次在线校验成功的时间）。不写日志，不返回给浏览器。

**校验时机**：本机服务启动时、以及浏览器请求 `/api/state` 或 `/api/auth/status` 且距上次校验超过 5 分钟时：

1. access 未过期 → `GET /auth/me`；已过期 → `POST /auth/refresh`。
2. 返回 401 / 403 → 会话失效，清除 `session.json`，回到登录页（学习数据不删）。
3. 网络不通 / 超时（3 秒）→ 进入**离线宽限**：距 `last_verified` 不超过 7 天时继续使用，界面顶部显示“认证服务不可达，离线使用中”；超过 7 天则要求重新登录。

个人信息相关的本机接口（数据都在当前账号目录下）：

| 本机接口 | 作用 |
|---|---|
| `POST /api/profile/name` | `{name}`（1–20 字）。先调 `/auth/profile` 改账号昵称，再写本机库；认证服务连不上时只改本机并返回 `notice` |
| `POST /api/profile/meta` | `{age?, gender?, major?, needs?}`，只改给出的字段。年龄为空或 6–100 的整数；性别、专业 ≤ 30 字，学习需求 ≤ 200 字；不合法 400 |
| `GET /api/profile/avatar` | 头像图片；没有时 404 |
| `POST /api/profile/avatar` | `{content}`（base64），仅 PNG / JPEG，≤ 1 MB，存为 `users/<用户ID>/avatar.png/.jpg`。浏览器先把超过 1 MB 的图等比缩到 512 像素以内再上传（PNG 仍超限时转 JPEG 逐级降质量），原图超过 20 MB 直接拒绝 |
| `DELETE /api/profile/avatar` | 恢复默认头像（显示名首字） |
| `GET /api/profile/<YYYY-MM>` | 读取某月档案；月份格式不合法返回 400 |
| `GET /api/profile/<YYYY-MM>/download` | 下载该月档案 `.md` |
| `POST /api/folders/<id>/rename` | `{name}`；内置文件夹和与科目同名的文件夹不可改名（科目靠同名关联文件夹） |
| `POST /api/materials/<id>/move` | `{folder_id}`；把资料移到另一个文件夹 |
| `POST /api/materials/<id>/meta` | `{title?, subject?}`；标题 1–80 字，科目须为已有科目或空串（不归科目）。内置核心资料不可改名（403），因为启动时按标题补导入 |
| `POST /api/materials/batch` | `{action: "move"/"delete", ids: [...], folder_id?}`；ids 1–200 个，目标文件夹不存在 404，不存在的资料跳过并计入 `missing`，返回 `{ok, done, missing}` |

资料管理页的搜索（标题 / 来源 / 科目）、按科目筛选、排序（最新 / 最早 / 名称 / 大小）都在浏览器端完成；勾选后可批量移动、批量删除，也可以把卡片拖到上方的文件夹标签上完成移动（拖动已勾选的卡片时带上全部勾选项）。

登录时以账号昵称覆盖本机显示名，所以在一台电脑上改了显示名，另一台电脑下次登录也会更新。

`app/data/users/<用户ID>/` 下的 `csla.db` 只有一条 sqlite 连接，本机服务是多线程的，`server.py` 的 `CurrentStore` 代理把所有 Store 调用串行化，避免并发请求把连接卡在未提交事务里（表现为所有写操作报 `database is locked`）。

### 6.3 按账号隔离数据

现状：`server.py` 全局 `STORE = Store()`，资料目录、档案目录是 `store.py` 的模块常量，所有数据在 `app/data/` 下且只有一个用户。

改为：

```text
app/data/
├── session.json
├── client.json            （可选）
└── users/
    └── <用户ID>/
        ├── csla.db        原 data/csla.db 的全部表，含 API Key 配置
        ├── materials/
        └── profile/
```

- `Store(db_path, data_dir=None)`：资料、档案目录改为跟随实例的 `data_dir`；不传时保持原来的 `app/data/`，`check.py` 等旧用法不受影响。
- 登录 / 切换账号时：新建该用户的 `Store`，执行与启动时相同的初始化（内置科目、文件夹、示例资料），并清空检索器缓存和回答缓存，防止串号。
- 未登录时，除 `/api/state`、`/api/auth/*`、`/api/heartbeat`、`/api/client-closed` 外，所有 `/api/*` 返回 401 `{"error":{"code":"auth_required"}}`，前端据此回到登录页。
- **旧数据迁移**：如果存在升级前的 `app/data/csla.db`，第一个在本机登录的账号接收它——把 `csla.db`、`materials/`、`profile/` 移到该账号目录，把 `materials.path` 中的旧路径前缀替换为新目录，然后写 `app/data/users/.legacy_migrated` 标记，之后不再迁移。
- 开发调试可用 `python server.py --no-auth` 跳过登录，行为与改动前一致（单用户、数据在 `app/data/`）。

### 6.4 页面流程

```text
打开页面 → 欢迎动画
   ├─ 未登录 → 登录 / 注册页 ──成功──┐
   └─ 已登录 ───────────────────────┤
                                    ├─ 该账号没配 API Key 且非 --mock → API Key 页
                                    └─ 已配置 → 「开始学习」→ 主界面
```

- 登录页和注册页是同一张卡片的两个标签；注册页有“确认密码”。密码框右侧有“显示 / 隐藏”按钮，下方有“记住用户名”。
- 侧栏底部新增“修改密码”“登录设备”“退出登录”；侧栏名片显示昵称（无昵称显示用户名）。窄屏（< 900px）只保留“退出登录”。
- “登录设备”弹窗列出该账号的全部会话，可让单台下线或“退出其他所有设备”；弹窗左下角“注销账号…”打开注销确认，需要输入密码并再输入一遍用户名。
- 任意接口返回 401 `auth_required` → 回到登录页。
- 离线宽限期间顶部显示提示条。

## 7. 账号运维

管理操作只在开发者电脑上用命令行完成，不开放网络接口：

```bash
cd AIassistant/auth_server
python auth_server.py users                         # 列出账号
python auth_server.py disable <用户名>               # 禁用并撤销全部会话
python auth_server.py enable <用户名>
python auth_server.py reset-password <用户名>        # 交互输入新密码，撤销全部会话
```

**密码找回**：本项目不收集邮箱 / 手机号，无法自助找回。用户联系管理员，管理员核实身份后用 `reset-password` 设临时密码，用户登录后自行修改。

**备份**：停服后复制 `auth_server/data/auth.db` 即可；或在运行时用 `sqlite3 auth.db ".backup backup.db"`。

## 8. 部署

### 本机演示（一台电脑）

```bash
python AIassistant/auth_server/auth_server.py              # 终端 1，监听 127.0.0.1:8740
python AIassistant/app/server.py --open                    # 终端 2
```

Windows 下双击 `AIassistant/启动.bat`（或 `run.bat`）会先在最小化窗口里启动认证服务，再启动学习助手；认证服务已在运行时，新开的那个窗口因端口占用自行退出，不影响使用。

### 同一局域网

开发者电脑：

```bash
python auth_server.py --host 0.0.0.0 --port 8740
```

放行防火墙 8740 端口。用户电脑：`python server.py --auth-server http://<开发者局域网IP>:8740`，或写入 `app/data/client.json`。

局域网内是 HTTP 明文传输密码，**只适合课堂演示**。

### 异地 / 公网

必须走 HTTPS，二选一：

1. 内网穿透或反向代理（如 frp、Nginx、Caddy）在入口处终止 TLS，认证服务仍监听本机 HTTP。推荐，证书由代理管理。
2. 认证服务直接加载证书：`python auth_server.py --host 0.0.0.0 --cert fullchain.pem --key privkey.pem`。

客户端配置 `https://` 地址。使用域名而非 IP，方便日后迁移到云服务器。只对外暴露认证端口，不暴露数据库文件。

## 9. 在线与离线

| 情况 | 行为 |
|---|---|
| 认证服务不可达，用户未登录 | 登录 / 注册提示“认证服务不可达（地址）”，不提示密码错误 |
| 认证服务不可达，已登录且 7 天内校验过 | 正常使用，顶部提示离线 |
| 离线超过 7 天 | 回到登录页；学习数据保留，重新登录后恢复 |
| 离线期间账号被禁用 / 改密 | 恢复联网后的下一次校验时生效 |
| DeepSeek 调用 | 始终需要互联网，与登录状态无关 |

## 10. 测试

### 自动化（`python test_auth.py`）

在临时目录启动认证服务（随机端口），不碰真实数据：

1. 注册成功；用户名大小写不同视为重复（409）；非法用户名、弱密码返回 400。
2. 正确密码登录成功；错误密码与不存在的用户返回同样的 401 和提示。
3. 同一用户名连续 5 次失败后返回 429。
4. `/auth/me` 用 access token 成功；伪造 token 401。
5. 刷新后拿到新 token；旧 refresh token 再刷新失败；旧 access token 失效。
6. 退出后 token 失效。
7. 改密码：旧密码错误被拒；成功后其他会话失效，新密码可登录。
8. 禁用账号：已有会话失效，登录返回 403。
9. 数据库中不存在明文密码和明文 token。
10. 本机客户端：会话持久化、离线宽限（未超期 / 超期）、401 清会话。
11. 数据隔离：两个账号各写一条数据互不可见；旧数据迁移给首个登录账号。
12. 改昵称：认证服务与本机客户端会话同步更新；超长昵称 400。
13. 本机个人信息 / 资料接口：显示名、头像上传与恢复、档案按月查看与下载（非法月份 400、路径穿越 404）、文件夹改名规则、资料移动。
14. 并发：8 个线程同时读写本机接口，不出现 500。
15. 登录设备：列表含设备名、当前会话排第一；不能让当前会话下线（400）；单台下线、退出其他所有设备后对应 token 失效。
16. 注销账号：密码错误 401 且计入限流；成功后账号和会话删除、用户名可重新注册；本机客户端清会话；`purge_user_data` 拒绝非法 uid、能删除合法账号目录。
17. 本机接口：个人信息字段校验（年龄越界 / 非整数、超长字段 400，允许清空）；资料改名 / 改科目（科目不存在、空标题 400，不存在 404，内置核心资料改名 403）；批量移动 / 删除（非法 action、ids 400，目标文件夹不存在 404，`missing` 计数）。

### 手工验收

1. 启动两个服务，注册 → 自动进入 → 填 Key → 主界面显示昵称。
2. 退出登录 → 回登录页；用错密码登录看到统一提示。
3. 再注册第二个账号，确认看不到第一个账号的对话和资料。
4. 停掉认证服务后重启学习助手（或等 5 分钟后刷新页面）：已登录状态继续可用，顶部出现离线提示。
5. 管理员禁用账号 → 距上次在线校验超过 5 分钟后，用户下次刷新页面即回到登录页；期间若修改密码会立即回到登录页。

`check.py` 在未登录时检查 `/api/*` 返回 401，登录后检查各只读接口 200。

## 11. 边界与限制

1. **登录不等于数据同步。** 换一台电脑登录同一账号，原电脑的聊天和资料不会出现。
2. **不是防破解机制。** 用户能改自己电脑上的程序（例如用 `--no-auth`），登录只用于规范正常使用流程和区分本机多个使用者，不保护本地数据不被同机其他人读取。
3. **局域网 HTTP 明文。** 公网使用必须配 HTTPS。
4. **频率限制在内存。** 认证服务重启后计数清零；多进程部署时不共享。
5. **开发者电脑需要维护。** 关机即无法注册和首次登录；需定期备份 `auth.db`。
6. **本方案不涉及模型训练**，账号、推理、学习数据是三件独立的事。
