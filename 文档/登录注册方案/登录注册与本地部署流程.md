# 登录注册与本地部署流程

日期：2026-10-31  
项目：计算机课程学习助手（CSLA）  
状态：方案说明，尚未实施

## 1. 总体方案

在开发者自己的电脑上运行一个账号认证服务器，账号数据库也保存在这台电脑上。用户在自己的电脑上安装、运行学习助手，通过网络向认证服务器注册或登录。

认证服务器只负责账号、登录会话和登录状态，不负责运行学习助手，也不需要中转聊天内容和模型请求。

```text
用户电脑：学习助手客户端
    │
    │ HTTPS：注册、登录、刷新凭证、退出登录
    ▼
开发者电脑：账号认证服务
    │
    ▼
开发者电脑：账号数据库

登录成功后：
用户电脑 → 本地模型
        或 → 用户配置的 DeepSeek API

课程资料、聊天记录、错题、总结 → 用户电脑的本地存储
```

## 2. 注册流程

1. 用户打开学习助手，进入注册页面，填写用户名、密码和确认密码。
2. 客户端检查输入是否完整、两次密码是否一致，通过 HTTPS 提交注册请求。
3. 服务器再次检查输入、账号格式和用户名是否重复；客户端检查不能代替服务器检查。
4. 服务器使用专用密码哈希算法处理密码，并保存哈希及必要参数，绝不保存明文密码。不得用普通快速哈希直接代替密码哈希算法。
5. 数据库创建账号，生成稳定且唯一的用户ID，记录账号状态和注册时间。
6. 服务器返回注册结果；成功后引导用户登录，失败时显示明确的处理提示。

## 3. 登录流程

1. 用户填写用户名和密码，客户端通过 HTTPS 发送给认证服务。
2. 服务器查询账号，校验密码哈希，并检查账号是否被禁用。
3. 登录失败时返回统一的凭证错误提示，限制连续失败尝试，避免泄露账号是否存在。
4. 登录成功后创建登录会话，返回登录凭证（token）、有效期，以及用户ID、昵称等必要信息，不返回密码或密码哈希。
5. 客户端安全保存凭证并进入主界面，不保存明文登录密码。
6. 客户端根据用户ID选择对应的本地数据目录，避免同一台电脑上切换账号时混用学习数据。

## 4. 保持登录、刷新与退出

- 客户端再次启动时，先检查已保存的登录凭证，按约定向服务器验证或刷新。
- 凭证过期且无法刷新时，要求重新登录，不必在每次业务操作中重复发送用户名和密码。
- 用户退出登录时，客户端清除本地凭证，并请求服务器撤销对应会话。
- 用户被禁用或密码重置后，服务器应能撤销相关会话。
- 登录凭证属于敏感信息，应使用操作系统提供的安全存储机制，避免写入普通日志。
- 具体凭证格式、有效期、刷新策略和多设备登录规则，在实现时统一确定。

## 5. 数据保存位置

| 开发者电脑上的认证服务 | 用户自己电脑上的学习助手 |
|---|---|
| 用户ID、用户名、昵称 | 课程资料与检索索引 |
| 密码哈希及必要参数 | 聊天记录、错题、章节内容 |
| 账号状态、注册时间 | 学习总结和学习档案 |
| 登录会话、到期时间、撤销状态 | 本地模型及个人模型配置 |
| 必要的登录审计记录 | 个人 DeepSeek API Key（安全保存） |

账号数据库只允许认证服务访问，不向互联网直接开放数据库端口。学习内容默认不上传到认证服务器。

## 6. 网络部署方式

### 同一局域网

认证服务监听指定地址与端口，用户客户端配置开发者电脑的局域网地址。需设置防火墙规则，并确保双方网络可互通。

### 不同网络或异地使用

认证服务需要稳定的公网访问入口，可选择公网IP配合端口映射，或内网穿透服务。客户端应通过固定地址和 HTTPS 访问，只暴露必要的认证接口。

使用域名有利于后续迁移：将认证服务迁移到另一台电脑或云服务器时，可以调整域名指向，减少客户端配置变动。

## 7. 在线与离线行为

开发者电脑关机、休眠、断网或认证服务停止时，新用户无法注册，未登录用户无法完成在线登录。

对于已经登录的用户，可以设计一定期限内的离线使用能力，但需明确：

- 离线允许使用哪些本地功能，授权期限多长。
- 断网时明确提示认证服务不可达，不误报为密码错误。
- 离线期间无法立即获取账号封禁或会话撤销通知。
- 本地模型可在具备完整运行环境时离线工作；DeepSeek API调用仍需要互联网。
- 离线授权过期后的处理方式，不应造成用户学习数据丢失。

## 8. 建议的认证接口

以下是待实现的接口约定，不表示当前程序已经提供这些接口。

| 接口 | 用途 | 主要返回内容 |
|---|---|---|
| POST /auth/register | 创建账号 | 用户ID、注册结果 |
| POST /auth/login | 验证账号密码 | 登录凭证、有效期、用户信息 |
| GET /auth/me | 获取当前登录信息 | 用户ID、昵称、账号状态 |
| POST /auth/refresh | 刷新登录凭证 | 新凭证及有效期 |
| POST /auth/logout | 撤销当前会话 | 退出结果 |

所有接口都需要输入校验和合理的请求限制。密码修改、密码找回和管理员禁用账号的流程，需要在实现前补充确定。

## 9. 边界与限制

1. **登录不等于数据同步。** 同一账号在另一台电脑登录后，原电脑上的聊天和资料不会自动出现。跨设备同步需要单独设计。
2. **本地部署不是强制防绕过机制。** 用户能够修改自己电脑上的程序，登录机制适合管理正常访问流程，不能单独保证本地功能无法被绕过。
3. **开发者电脑需要维护。** 需考虑长期在线、数据库备份、凭证保护、服务恢复和地址稳定性。
4. **本方案不涉及模型训练。** 账号认证、模型推理和学习数据管理是独立职责。

## 10. 实施顺序

1. 确定账号字段、会话有效期、离线规则及密码找回方式。
2. 在开发者电脑建立认证服务及账号数据库。
3. 完成注册、登录、验证、刷新、退出接口。
4. 在学习助手增加注册登录页面，并按用户ID隔离本地数据。
5. 在局域网验证正常登录、错误密码、重复注册、凭证过期和退出流程。
6. 配置公网访问与 HTTPS，再验证异地使用、断网和服务重启。
7. 增加数据库备份、日志脱敏和会话撤销测试。

课程演示阶段可以使用开发者电脑承载认证服务；需要长期供多人使用时，可将同一认证服务迁移到云服务器。
