项目范围本期面向 PC 端，范围如下：（1）本地运行的计算机课程学习助手，用于课后自学与复习；配置 DeepSeek API Key 后，基于导入资料问答并按科目、章节学习。（2）包含资料管理、检索引用、四科19章的讲解与练习、判分错题、小结、自然语言操作、学习档案及九份文档。不含账号体系、模型训练、本地推理、OCR、开放题批改及手机适配。（3）适用于组成原理、网络、操作系统和数据结构的辅助学习，不替代教材或教师。平行版本独立维护，不重复计入工作量。1.2 项目目标第8周交付可运行的 PC 版本：另一台电脑按说明启动；问答引用可追溯；四科19章可进入，抽查讲解、作答、判分及小结。演示资料整理和章节修改，删除需确认；九份文档与实际一致。以测试、操作和评审记录验收。上述为计划目标，未验收不得记为已通过。1.3 客户与最终用户介绍非合同课程项目，客户与验收方为课程指导教师，依据课程要求评审。用户为计算机专业本科生，主要使用 Windows 电脑，自备课程资料及 API 账号，用于课后复习。需求来自课程要求与小组讨论，未提供可核验的访谈或问卷记录。1.4 开发方介绍开发方为三人课程小组：A协调需求，B负责科目学习，C负责工程与测试。真实姓名、学号、班级、组长及联系方式待小组确认。1.5 制约遵循课程模板与事实约束，使用 HTTP、JSON、SSE；Git 管理、PR评审。平行版本分支隔离，受限课件不公开分发。按八周、三人、每人每周9小时估算，日期与工时待确认；依赖已有电脑、Python、网络及API额度，无GPU训练和手机适配。2. 项目过程定义2.1 过程模型裁剪 SPP 模型，按周迭代：需求细化 → 设计 → 实现 → 自测 → 文档与评审。第1周确定范围，第2—4周完成核心链路，第5—6周完善工具与界面，第7—8周测试交付。第6周末冻结功能，此后以修复和文档为主。2.2 方法与工具采用轻量实现和交叉评审；每轮保留可演示版本，需求变化记录原因、影响及处理结论。所列工具用于计划实施，不代表测试已执行。过程域 | 方法与工具 |  | 需求与设计 | Markdown、用例与接口表；JSON 接口约定 |
