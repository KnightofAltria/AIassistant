## 1 项目介绍

### 1.1 项目范围

**是什么**：一个在个人电脑本地运行的 AI 学习助手。学生填写自己的 DeepSeek API Key 后进入系统，导入课程资料即可获得带出处的问答；按科目与章节学习、做练习、看小结；并能用一句话让 AI 整理资料、增删章节。

**包含的内容**

1. 资料管理：核心资料（core）+ 四学科文件夹，导入、切片建索引、点击打开源文件、文件夹与资料删除。
2. 资料问答：检索 → 组装证据 → 流式生成 → 服务端校验引用编号是否合法。
3. 科目学习：四门课（计算机组成原理、计算机网络、操作系统、数据结构）共 19 章，大纲、讲解、单选练习、判分、错题、章节小结、推荐学习视频。
4. 工具化 AI：15 个工具（资料增删移、按科目归类、抓取网页、科目与章节增删改、出题），删除类操作强制二次确认。
5. 个人信息：年龄/性别/专业/需求四栏目，按月学习者档案，易错提示本。
6. 交付件：可运行代码、九份项目文档、每日修改日志、启动脚本与安装说明。

**不包含的内容**：登录注册与账号体系；本地大模型推理；模型微调训练；原生移动 App；OCR 与多模态；开放题自动批改；代码执行沙箱；多用户高并发；自动全网爬取。

**适用领域**：计算机专业本科课程的课后自学与练习，以本地资料为依据的问答。
**不适用领域**：需要权威答疑的正式教学场景、任何替代教材的场景、其他学科。

**关于两个版本**：本计划的工作量与进度只针对本体 `AIassistant/`。平行版 `AIassistant2/` 由另一 AI 在 `gpt-version` 分支并行产出，作为技术路线对照，不计入本期 WBS 与工作量。

## 2 项目过程定义

### 2.1 过程模型

采用**每周一轮的小步迭代**，每轮固定五个动作，每周必须产出一个可运行、可演示的片段：

```
需求细化 → 设计（含接口/数据）→ 实现 → 自测 → 文档与评审
   ↑                                                │
   └──────────── 下周计划的输入 ←───────────────────┘
```

- 第 1 周：范围冻结、技术选型验证、资料清单与采集。
- 第 2–4 周：核心链路（检索、问答、科目学习）逐条打通。
- 第 5–6 周：工具化 AI、界面与动效、个人信息。
- 第 7–8 周：测试、安装验证、九份文档与答辩材料。
- 第 6 周末功能冻结，之后只做修复与文档，不加新功能。

### 2.2 方法与工具

| 过程域 | 方法与工具 |
|---|---|
| 需求与设计 | Markdown 文档；用例与接口用文字 + 表格描述；接口契约用 JSON |
| 版本控制 | Git + GitHub，SSH 协议；分支 `main`（本体）与 `gpt-version`（平行版） |
| 实现 | Python 3.10+ **标准库**（`http.server`、`sqlite3`、`urllib`）；前端原生 JS/CSS/HTML，无构建步骤 |
| 数据 | SQLite 单文件库；资料与档案按文件落盘 |
| 模型接入 | DeepSeek `chat/completions`（流式 SSE + function calling） |
| 测试 | 自研 `check.py`（20 项静态与只读检查，零成本）与 `selftest.py`（44 项全链路，含模型调用） |
| 文档 | Markdown 为主，交付件用 python-docx 生成 Word |
| 协作 | 每周例会 + 周报；PR 评审；每日自动生成修改日志 |

选型原则：**只用实际会用到的工具**，不为展示而引入框架。因此未采用 Vue、Flask、向量数据库等方案，理由与验证记录见附录 C 的 CHG-003。
