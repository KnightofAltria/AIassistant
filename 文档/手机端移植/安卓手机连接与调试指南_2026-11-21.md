# 安卓手机连接与调试指南

日期：2026-11-21　项目：CSLA 学习助手　适用：Mac 与 Android 8.0 及以上手机

## 一、先连接手机

1. 打开手机“设置 → 关于手机”，连续点击“版本号”或“软件版本”7 次，按提示输入锁屏密码。不同品牌入口名称略有不同。
2. 返回设置，进入“开发者选项”，开启“USB 调试”。部分品牌还需要开启“USB 安装”。
3. 使用支持传输数据的数据线连接 Mac，解锁手机；若提示 USB 用途，选择“文件传输”。
4. 手机弹出“允许 USB 调试？”时，核对当前电脑后点击“允许”。个人电脑可勾选“始终允许使用这台计算机进行调试”。
5. 在 Mac 终端执行下面的命令。本机调试工具统一放在用户目录下，无须修改系统 Java 配置。

```sh
export ANDROID_HOME="$HOME/.local/share/csla-android-tools/sdk"
export PATH="$ANDROID_HOME/platform-tools:$PATH"
adb devices
```

正常结果：列表中出现手机序列号，后面为 `device`。状态含义如下。

| 结果 | 处理方式 |
| --- | --- |
| device | 已连接，可以安装和调试。 |
| unauthorized | 解锁手机并允许 RSA 授权；未出现提示时，重新插线，或在开发者选项中撤销 USB 调试授权后重新授权。 |
| offline | 重新插线，然后执行 adb kill-server、adb start-server，再检查。 |
| 列表为空 | 检查线缆是否支持数据、USB 调试是否开启，尝试另一根线或 USB 端口。macOS 通常不需要额外 USB 驱动。 |
| 出现多台设备 | 后续命令使用 adb -s 手机序列号，明确选择目标。 |

## 二、安装并打开应用

使用同一签名覆盖安装，可保留手机内的资料与学习记录。将下面的 APK 路径替换为本次交付安装包的实际路径。

```sh
adb install -r "/完整路径/CSLA-安卓调试版-0.1.1.apk"
adb shell am start -n cn.csla.mobile/.MainActivity
```

看到 `Success` 表示安装成功。应用内的学习服务直接运行在手机中，打开后不需要电脑启动 Python 服务，也不需要 adb reverse。首次可以离线阅读内置资料；模型提问或生成需要手机联网，并在应用设置中填写自己的 DeepSeek API Key。

若出现 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，说明手机上的旧版和当前 APK 签名不同。先找回旧签名并重新构建；不要直接卸载来绕过错误，卸载会删除手机学习库。若出现 `INSTALL_FAILED_VERSION_DOWNGRADE`，检查是否拿错旧 APK，并使用版本号更高且签名一致的构建。部分手机的 USB 安装需要在手机上额外确认。

## 三、用 Android Studio 单步调试

1. 若尚未安装 Android Studio，从 developer.android.com/studio 下载适合 Mac 的版本。
2. 点击 Open，选择仓库中的 `AIassistant/android` 目录。
3. 在 SDK Manager 中安装 Android SDK Platform 35、Build Tools 35.0.0 和 Android SDK Platform-Tools；本机已准备 SDK 时，可把 SDK Location 指向上一节的 sdk 目录。
4. 在 Settings → Build, Execution, Deployment → Build Tools → Gradle 中选择 JDK 17。具体的本机 JAVA_HOME 路径见交付目录中的调试环境文件。
5. 等待 Gradle Sync 完成，在设备下拉列表中选择已授权的手机，选择 app 配置，点击 Run 安装运行，或点击 Debug 进入断点调试。
6. Kotlin 断点可放在 MainActivity 的 goBack、launchLocal，或 PdfActivity 的 onCreate、render。Android Studio 的 Java/Kotlin 调试器不直接提供内嵌 Python 源码断点；Python 行为可通过临时库回归和必要的应用日志定位。

构建会下载 Gradle、Android 插件及 Chaquopy 依赖。Python 运行时随 APK 打包，手机无需单独安装 Python。项目支持 arm64-v8a 和 x86_64，不支持仅有 32 位 ABI 的手机。

## 四、查看应用日志与网页界面

原生层：在 Android Studio 打开 Logcat，选择手机并过滤 `package:cn.csla.mobile`。先清楚描述触发动作，再查看报错。

也可在终端运行：

```sh
adb shell pidof cn.csla.mobile
# 将上一步输出的进程号填入，例如 12345。
adb logcat --pid=12345
```

进程重启后需要重新获取进程号。若应用闪退，使用 `adb logcat -b crash -d` 查看系统崩溃记录。

网页层：打开手机中的调试版应用，然后在 Mac Chrome 地址栏打开 `chrome://inspect/#devices`，勾选 Discover USB devices，找到 CSLA 的 WebView 后点击 inspect。可查看 Elements、Console 和 Network，定位返回导航、界面布局与本地接口问题。只有 debug 构建开放 WebView 调试，release 构建关闭。

应用窗口禁止普通截图和录屏，这是现有私有学习资料保护设置。页面检查可以通过 WebView 调试器进行。共享调试日志或截图前，去掉 API Key、学习内容和会话凭据。

## 五、可选：无线调试

Android 11 及以上通常支持无线调试；电脑和手机需处于可互相访问的同一 Wi-Fi 网络。

1. 手机进入开发者选项 → 无线调试，开启开关。
2. 点击“使用配对码配对设备”，记下该页面显示的 IP、配对端口和配对码。
3. 终端执行下面的配对命令，按提示输入手机显示的配对码。
4. 返回无线调试主页面，使用主页面显示的连接端口执行连接命令。配对端口与连接端口通常不同。

```sh
adb pair 手机IP:配对端口
adb connect 手机IP:连接端口
adb devices
```

也可以在 Android Studio 的设备菜单选择 Pair Devices Using Wi-Fi，按二维码或配对码连接。手机重连 Wi-Fi 后地址或端口可能改变。调试完可关闭无线调试。

## 六、修复后在手机上按顺序验收

| 操作 | 应看到的结果 |
| --- | --- |
| 打开应用，进入科目、章节并连续返回 | 依次回到章节列表、科目列表、首页；首页再返回才退出。目录或弹窗打开时先关闭它们。 |
| 在已有讲义的章节重生成大纲，中途切后台再回来 | 旧大纲和已保存讲义保留；任务显示中断，可在前台重试。 |
| 删除测试章节或自建科目 | 对应任务记录消失；尚未结束请求的回调不会重新创建残留任务。 |
| 导入至少三页的 PDF，跳到第 3 页并滚动，再旋转手机 | 重建阅读页后仍显示原资料和第 3 页，滚动位置恢复。 |
| PDF 打开时按 Home，再执行 adb shell am kill cn.csla.mobile，然后从最近任务恢复 | 系统实际结束后台进程后，恢复阅读页仍可初始化学习库并打开原页。若命令未结束进程，本项不能算完成。 |
| 阅读 Markdown、文本、Word 或 PDF | 手机页面没有“用电脑上的程序打开”按钮；PDF 可打开手机原生阅读器，源文件仍可导出。 |
| 导入、导出文件并尝试系统返回、中文输入 | 文件选择器授权、保存结果、返回和输入法均正常。 |

后台取消会在下一次网络响应或超时后被检查，无法保证立刻中断已经发出的网络请求，也不能撤回已消耗的模型额度。真实模型验收会产生接口费用，可先完成离线流程。

## 七、签名与本地构建

调试签名现保存在 `android/.signing/debug.keystore`，不会被 clean 删除；旧 `app/build/debug.keystore` 会在 Gradle 配置阶段先迁移。该文件不进入 Git。不同电脑默认生成的签名不同，团队覆盖安装应使用同一份已有签名。

在 android 目录下构建：

```sh
export JAVA_HOME="/本机JDK17路径/Contents/Home"
export ANDROID_HOME="$HOME/.local/share/csla-android-tools/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$PATH"
./gradlew assembleDebug lintDebug
```

APK 输出为 `app/build/outputs/apk/debug/app-debug.apk`。使用其他已有签名时，传入 `-PcslaDebugKeystore=/绝对路径/debug.keystore`；显式指定不存在的签名会报错，不会悄悄生成另一份签名。

本次自动化检查覆盖临时库、模型替代响应、网页导航和构建检查；实际手机的 Keystore、原生 PDF 恢复、输入法、系统文件选择器以及真实模型调用，仍需按本指南验收。
