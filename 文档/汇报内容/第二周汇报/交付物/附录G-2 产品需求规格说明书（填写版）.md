0.5 术语与缩写解释

缩写、术语 | 解 释

1. 产品介绍

本产品是面向计算机课程的本地学习助手。

学生登录后导入课程资料，进行带出处问答、章节练习、错题复习和学习总结。资料、记录按账号保存在本机；生成服务调用 DeepSeek API。

针对课程材料分散、复习缺少反馈的问题，提供资料整理与学习记录闭环。课程目标为功能可演示、代码可安装、文档与实际一致。



2. 产品面向的用户群体

主要服务于计算机相关专业学生及课程项目评审人员。

学生具备基本浏览器和文件操作能力，可自行管理学习资料与 API Key；管理员负责账号状态和受限操作。

预期收益是减少资料查找与重复整理，集中查看练习结果；未开展正式用户调研，不估计采用率。



3. 产品应当遵循的标准或规范

遵循课程模板及项目提交约定。接口采用 HTTP/JSON，流式事件采用 SSE；数据库操作使用参数化 SQL。资料导入须有使用权限，模型回答需提示出处与证据不足，不替代教师结论。



4. 产品范围

包含登录与按账号隔离、资料导入及阅读、科目章节、检索问答、题目与作答、错题复习、总结档案、看板和工具调用。支持 TXT/Markdown/CSV/JSON/DOCX/PDF；扫描 PDF 无文字层时不承诺识别。不包含自训练模型、OCR、跨账号资料同步、云端学习数据备份及正式考试评分。



5. 产品中的角色

学生管理自己的学习内容；管理员仅增加账号管理和核心资料写权限。管理员修改本人核心资料不等于发布给所有学生。



角色名称 | 职责描述

学生 | 管理本人资料、对话、作答、档案；核心资料只读。

管理员 | 管理账号启停、密码重置；可修改本人核心资料。

认证服务 | 验证凭证、签发与撤销会话，返回角色。

指导教师／评审人 | 审阅需求、演示和测试记录，不预设系统管理权限。



6. 产品的功能性需求

6.0 功能性需求分类

按账号、资料、学习三个类别组织需求，以下标识用于设计和测试追踪。

功能类别 | 功能名称、标识符 | 描述

账号与权限 | FR-01 登录／FR-02 账号管理 | 注册、登录、修改密码、设备下线、注销；管理员启停及重置密码。

 | FR-03 个人信息／FR-04 清除记录 | 维护昵称、简介、头像；按类清除本人学习记录。

资料服务 | FR-05 导入与阅读 | 保存源文件，提取正文，Markdown/Word/PDF 阅读与下载。

 | FR-06 整理与审核 | 文件夹、搜索筛选、批量移动删除、排序、审核隔离与权限检查。

学习辅助 | FR-07 问答／FR-08 章节练习 | 带引用流式问答，科目章节与题目生成、作答反馈。

 | FR-09 至 FR-12 复习与扩展 | 错题复习、总结档案、看板可视化、工具式操作与费曼练习。



6.m 学习辅助功能

本节以完整学习流程定义需求；账号与权限、资料管理为前置能力。功能存在于当前代码不等于完成正式验收。

6.m.n 学习流程 FR-01 至 FR-12

名称、标识符 | 学习闭环 FR-01～FR-12

功能描述 | 登录并完成资料准备后，以科目/章节组织问答和练习，记录结果并支持复习；生成内容允许查看与校核。

优先级 | 高：账号隔离、资料、问答、练习；中：看板、费曼练习及工具辅助。

输入 | 用户名密码；用户选择的资料、科目章节、问题、答案；真实生成需有效 API Key。

操作序列 | 1. 登录并配置模型。2. 导入资料，待审核内容须通过后才检索。3. 提问并逐条查看出处。4. 生成练习并作答。5. 查看错题、总结和档案；按需整理资料或清除记录。

输出 | 引用与回答、题目和反馈、复习队列、近期总结和月度档案；失败时返回明确错误且不伪造成功。

补充说明 | 账号隔离按用户目录执行；核心写入在后端校验。资料缺失或证据不足须提示；模型不可达允许重试。mock 仅用于链路演示，不代表生成质量。



验收以独立测试账号验证主流程与异常分支，权限用学生及管理员分别执行；正式评审结论见附录B。

7. 产品的非功能性需求

7.1 用户界面需求

需求名称 | 详细要求

一致性 | 保留蓝白界面、SVG 图标、卡片首页与粒子欢迎页；导航和按钮语义一致。

状态反馈 | 区分账号登录、模型 Key 校验、加载、成功、失败与空状态；提交中禁用重复操作。

可操作性 | 阅读页支持刷新和前进后退；危险操作明确确认；窄屏内容不溢出。

7.2 软硬件环境需求

需求名称 | 详细要求

运行环境 | Python 3.10 或以上、现代浏览器；Windows 为当前主要演示环境。

网络与端口 | 本地 8737 网页服务和 8740 认证服务可用；真实模型调用需要网络及有效 Key。

存储 | 本机可写目录；容量随资料增长。硬件最低资源未通过容量测试确定。

7.3 产品质量需求

主要质量属性 | 详细要求

正确性 | 按需求标识验证成功与失败场景，生成内容不保证事实完全正确。

健壮性 | 拒绝空输入、超限文件、非法参数和越权访问，说明恢复方式。

可靠性 | 关键写操作使用事务；删除与源文件清理一致，断连不使服务崩溃。

性能，效率 | 流式反馈减少等待；采用检索与回答缓存。吞吐量及响应时限尚未正式量测。

易用性 | 统一导航、空状态和确认提示；首次使用区分账号密码与 API Key。

清晰性 | 模块、接口及错误信息可追踪，文档对应当前源码。

安全性 | 密码哈希存储、角色和目录隔离；公网部署另需 HTTPS，禁止暴露密钥。

可扩展性 | 新增资料类型、模型或学习功能通过对应模块扩展，不更改既有数据含义。

兼容性 | 现代浏览器为目标；复杂 Word/PDF 版式和浏览器兼容性须实际验收。

可移植性 | 后端以标准库实现；Windows 启动脚本及本机打开功能需平台适配。

数据与验收 | 数据范围：核心资料非跨账号同步库；正式模型质量与用户验收待完成。

7.n 其它需求

运维要求：运行数据、密钥和会话不得提交 Git；目录改名或切换副本前应停止旧服务，避免 8737/8740 端口复用造成连接到错误账号库。



附录A：需求建模与分析报告

以角色用例和资料状态转换描述需求，不依赖特定建模软件。

A.1 需求模型1

用例关系：学生 → 登录 → 导入个人资料 → 提问并查看引用 → 练习 → 错题复习 → 总结与档案；管理员 → 管理账号、维护本人核心资料。认证服务为外部协作角色，模型服务负责生成。

A.n 资料与权限状态模型

资料状态：导入 → 待审核或可用；待审核 → 审核通过 → 加入检索；编辑、移动、删除或审核变化 → 索引版本递增 → 缓存失效。权限条件：本人普通资料可写，学生核心资料只读；管理员可写本人核心资料。删除需确认，清除记录不得影响资料和其他账号。
