计算机课程学习助手需求与可行方案

建议采用“现成小模型＋课程资料检索＋错题统计＋一次轻量微调”。三人八周完成演示交付版具有可行性，难度中等。主要工作在前后端联调、资料整理和安装测试。本结论是设计审查，尚未实测训练效果或系统性能。

课程要求完成需求、设计、编码、测试、部署与规范材料，评分包括文档 30 分、参与程度和模块质量等 50 分、中期汇报 5 分、讲评 15 分。课件没有要求所有项目都必须训练大模型。AI 与微调来自所给选题方案；本版保留一次实验以覆盖该方向。

按本次明确要求：三人大学生团队、只保证计算机专业内容、功能具备即可、以交付为主。项目范围统一为计算机相关内容，包括本科专业课程与计算机前沿专题；不包含文史、语言等其他学科。课程目录可逐步覆盖程序设计、数据结构与算法、离散数学、数字逻辑、计算机组成、操作系统、计算机网络、数据库、软件工程、编译原理、信息安全和人工智能基础。前沿专题可包括大模型与RAG、智能体、云原生与分布式系统、网络安全等。目录表示支持方向，不代表已有完整资料或全部课程均已通过验收。

为保持三人八周交付规模，首版演示采用数据结构、数据库基础各选定章节，加一个“大模型与RAG”前沿专题。其余计算机专业课程通过同一导入和检索流程逐步扩充，不为每门课单独开发系统。

2 模型基座

用途选择原因
本地生成与微调Qwen/Qwen3-4B-Instruct-25074B 指令模型、非思考模式，适合作为中文计算机基础解释的候选
语义检索BAAI/bge-small-zh-v1.5中文小模型，可在 CPU 运行，512 维、最大 512 token

Qwen 官方模型卡确认 4.0B 参数与非思考模式。是否满足本课程内容，应先用 20 道目标问题检验；不能仅凭模型名保证算法推导和 SQL 都正确。生成总上下文先限制为 4096 token，不因模型支持长上下文就使用最大长度。

未微调模型可用 Ollama 或独立推理进程；微调产物优先用 Transformers＋PEFT 加载并提供本地 HTTP 服务，避免额外格式转换。Ollama 不会自动加载任意 PEFT 适配器。

3 数据规模

数据建议规模作用
RAG 资料首版两门课程加一个前沿专题合计约 10–20 份、100–200 页文字，约 300–1000 切片可更新知识库；实际切片数取决于文字密度
微调数据总计 500 条：400 训练、50 验证、50 测试只覆盖数据结构有限知识点的教学表达
演示题库30 道人工核对单选，数据结构 20、数据库 10评分、错题、复习演示
RAG 验收40 问：两门课程各 12 道可回答、3 道不足；前沿专题 6 道可回答、4 道不足不混入训练数据
学习建议验证6 组预设作答序列检查统计规则，不训练模型

500 条是实验预算，不是保证效果的下限。400 条训练建议分为概念解释 100、分步提示 100、错误纠正 100、按给定材料回答 60、资料不足处理 40。按原题族分组后再划分集合，改数字或改措辞的题目不得跨集合。

样本保存来源、知识点、题族和审核人。合成内容逐条核对，不收集私人聊天训练。确实只能完成 250 条时，可调整为 200/25/25，并同步文档，结论限于训练流程跑通。

资料入库不等于微调。微调改善讲解方式，新增知识通过 RAG 导入。BGE 切片按其 tokenizer 约 300–400 token、重叠 50 token，标题也计入长度，不能沿用原方案最长 700 token 而被静默截断。

4 训练和设备

起始配置：QLoRA，4-bit NF4，rank 8，alpha 16，dropout 0.05，学习率 1e-4，序列 1024，micro batch 1，梯度累计 16，最多 2 轮，开启梯度检查点。使用模型 chat template，只对回答部分计算监督损失。BF16 依赖硬件支持，不支持时验证 FP16。

先用 20 条检查训练、保存和重新加载。400 条训练、有效 batch 16 时每轮约 25 个优化器步骤，两轮约 50 步，不含 packing 等影响。这是很小的实验，不保证提升。先测 20 步耗时再估算整体，训练等待时间与人工时间分开。

建议借用 16GB NVIDIA GPU 做短序列试训，24GB 更宽裕，系统内存建议 32GB。低于 16GB 需缩短序列和实测，不能承诺必定可运行。本地 4-bit 推理可从 8–12GB 显存、16GB RAM、单并发试起；CPU 可验证但可能很慢。这些是预算估计，尚未实测。

无 GPU 先做 API＋RAG，再借用或短租训练设备；不建议为课设买显卡。未实际训练就将微调标未完成，不能用调用 API 冒充微调。

5 最简技术方案

Vue 页面 → FastAPI 单体 → SQLite 业务与切片；后端调用本地嵌入和远程或本地生成服务。前端构建后由后端同源提供。一个业务进程、一份定时器。

查询时按课程和 active 文档过滤向量，NumPy 点积计算相似度，取 top 4，将原文与来源编号交给模型。几百至千段资料无需专用向量库或重排。向量与正文同存 SQLite，发布用单事务避免文件索引不同步。

问答先显示加载状态，完成后整段展示，不做流式回放。模型只能选择后端给出的引用编号；编号合法不等于支持结论，人工测试分别检查内容正确与出处。

学习规则：每知识点最近最多 5 道不同题目的首次作答，少于 3 道显示证据不足，正确率低于 60% 推荐复习。重做用于错题复习状态，不反复累计首次正确率。

6 原方案可行性与难度

原方案的 RAG、微调、诊断证据和审核更新职责分离合理，但三类学科、30 多个逻辑实体、任务租约、outbox、知识快照、流式回放和离线 PWA 对本次目标偏重。原估算 300 人时依赖现有经验和可用资料，不能当成保证。

本地 OpenAPI 包含 29 条路径、39 个 schema，内部引用检查未发现无法解析项；这只说明契约有组织，不证明系统可运行。当前文件夹没有该系统源代码、正式训练集或模型适配器。旧方案关于参考仓库的审阅不等于本次重新运行验证。

本版删除跨学科承诺、复杂诊断状态机、私有资料上传、先修图谱、多级回滚、高并发和离线安装能力；保留审核、撤回、错题与两模式等可演示闭环。

7 工时与验收

规划 180–240 人时，基线 216，约每人每周 9 小时。A 主问答与界面，B 主资料更新与部署，C 主练习和模型实验，每人都参与自己模块的设计、代码、测试和文档。最后两周留给验证与提交。

模型训练与验收方案

用一次小规模实验验证轻量微调并观察教学表达变化，不从头预训练。基座Qwen/Qwen3-4B-Instruct-2507，知识通过RAG，BGE冻结。

1 数据

500条目标，400训练、50验证、50测试，按题族拆分。训练分布解释100、提示100、纠错100、材料问答60、不足40。只覆盖数据结构选定章节。保存知识点、来源、题族与审核人。

本包5条原创格式示例不计正式数据。测试不能由训练题改数字组成。RAG库可含测试所需知识，但不能放专门测试答案和评分量规。只将审定messages送训练，元数据留账本。

2 训练配置

Transformers支持Qwen3，PEFT/bitsandbytes兼容验证后锁版本。prepare_model_for_kbit_training后加入LoRA，target_modules=all-linear，rank8、alpha16、dropout0.05。NF4、double quant、seq1024、batch1、accum16、lr1e-4、最多2轮、梯度检查点、seed42。硬件支持才用BF16，否则验证FP16。

20条先检查参数确实更新、答案不被截断、保存重载。用原chat template，仅对assistant计算监督损失。400条、有效batch16约每轮25步，实验很小，不保证提升。

建议借用16–24GB显存、32GB RAM。参数量乘4bit不是训练总显存，激活和优化器另占资源；先实测20步耗时和峰值，再估算。

3 对照与交付

最小两组为基础+RAG、微调+RAG，同50条独立测试、检索快照和生成参数。人工盲评事实、清晰度、提示、纠错及引用。时间允许补无RAG两组，不是本版必做。

保存数据及哈希、来源、环境锁文件、配置、日志、adapter、加载命令和评价表。适配器绑定精确基座revision。新进程加载可推理是验收点，不能只展示命令。

0 文档介绍

1 系统概述

浏览器页面调用FastAPI，SQLite保存业务和切片，BGE提供嵌入，远程或本地生成模型组织回答。评分、错题和学习建议由普通程序完成。

2 设计约束

三人八周、无专职运维，支持计算机本科专业课程及前沿专题，首版以两门课程及一个前沿专题验证。不引入微服务、外部消息队列或专用向量数据库。业务服务只运行一个进程，防止定时器重复；未来扩多进程需重新处理调度与数据库写竞争。

3 设计策略

4.1 users和sessions

4.3 chunks

5 安全性设计

浏览器不访问数据库文件；私人记录按登录用户过滤，不接受客户端user_id冒充身份。管理员维护公共内容，不因此自动开放私人对话。

作答在一个事务中查提交键、读题目、评分、写首次/重做；唯一冲突读取已有结果。审核先在事务外解析及嵌入，成功后事务写文档、切片、候选状态及通知，重复审核返回已有结果。

本人清除限制user_id，事务删除其messages、conversations和attempts，不动公共内容。清除时取消本人未完成请求，写回前核验会话仍存在，防止数据被旧请求复活。

6 优化

索引documents(course_id,status)、conversations(user_id,course_id)、attempts(user_id,question_id,created_at)、questions(course_id,active)、update_candidates(status)。约1000切片内先用线性点积，超规模再实测评估向量索引。

7 管理维护
