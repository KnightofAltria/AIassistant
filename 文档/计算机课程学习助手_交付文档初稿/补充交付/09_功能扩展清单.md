## 二、逐项说明

### EXT-01 复习队列（间隔重复）

- **为什么**：错题本原来只"记"，不"用"；答错之后没有任何机制让人再看一次。
- **做法**：新增 `reviews` 表；答错自动入队（`POST /api/attempts` 内联动），评分 `again / good / easy` 分别对应"退回一阶段 / 前进一阶段 / 前进两阶段"，间隔取 `1/3/7/15/30` 天。
- **接口**：`GET /api/review`、`POST /api/review/grade`
- **页面**：学习看板 →「复习队列」，三个按钮直接评分。
- **代码**：`store.py`（`add_review` / `list_due_reviews` / `grade_review`）、`extras.py`（`srs_next`）

### EXT-02 章节掌握度

- **为什么**：只有"正确率"一个数字不够，看不出哪一章该补。
- **做法**：按章节聚合 `attempts`，四档判定：未练习（0 次）/ 薄弱（<60%）/ 巩固中（60%~84%）/ 已掌握（≥85%）。
- **接口**：`GET /api/dashboard`（含 `mastery`）
- **页面**：看板进度条 + 状态徽标。

### EXT-03 今日建议

- **为什么**：学生打开软件第一件事通常是"我今天该干嘛"。
- **做法**：纯规则打分排序，不调用模型、不产生费用：到期复习 100 分 > 薄弱章节 80 分 > 未练章节 60 分。
- **接口**：`GET /api/dashboard`（含 `recommend`），可一键跳到对应章节。

### EXT-04 检索详情面板

- **为什么**：这是本次最推荐的扩展——评审最常问"它凭什么这么回答"。
- **做法**：对话流新增 `retrieval` 事件，携带检索式、命中片段、BM25 得分、阈值、是否判定资料不足；前端折叠展示。
- **接口**：`POST /api/chat/stream`（新增 `retrieval` 事件）
- **页面**：每条回答下方的「检索详情」。

### EXT-05 多查询改写

- **为什么**：一句口语化提问常常召回很差（"内存校验错到底是中断还是异常"这类）。
- **做法**：规则化拆分——原句、去掉"什么是/为什么/怎么"等疑问词后的核心、按标点切开的子句；子句结果与主检索结果合并，主检索排序在前、原始分数保留，因此**资料不足判定不受扰动**。
- **代码**：`rag.rewrite_queries` / `rag.search_multi`
- **说明**：这是规则实现，不是模型改写，好处是零延迟零成本、离线可用。

### EXT-06 拒答阈值可调

- **做法**：`INSUFFICIENCY_FLOOR` 从常量变为可配置（`config.refuse_threshold`），`POST /api/config` 接受该字段。
- **意义**：调大更容易说"资料不足"，调小更容易硬答，方便做验收对比。

### EXT-07 回答风格切换

- **做法**：`prompts.STYLE_SUFFIX` 三套后缀拼在 `CHAT_SYSTEM` 之后；前端下拉随请求发送 `style`。
- **三种风格**：简明（结论优先）/ 详解（结论→为什么→推导→易错点）/ 苏格拉底式（不直接给答案，先反问）。

### EXT-08 docx 导入

- **做法**：前端读文件为 base64 → `POST /api/materials/import` → 服务端 `zipfile + ElementTree` 解析 `word/document.xml`，按段落拼回纯文本；老式 `.doc` 明确报错提示另存。
- **代码**：`extras.docx_to_text`、`server._import_upload`
- **已验证**：生成 → 上传 → 解析 → 回读正文，内容一致。

### EXT-09 / EXT-10 资料版本、过期提醒与重新抓取

- **做法**：`materials` 增加 `hash`、`fetched_at`、`status` 三列（含老库自动补列与历史 hash 回填）；来源超过 30 天未抓取的在资料页顶部提示；`POST /api/materials/{id}/refresh` 重新抓取并用 hash 判断内容是否真的变了，没变就不动索引。

### EXT-11 审核后入库

- **做法**：导入时可勾选"先存为待审核"，三态 `pending / approved / rejected`；资料页顶部列出待审项，一键通过或驳回；对应设计文档里"新增资料须人工审核后进入 RAG"的要求。

### EXT-12 全文检索页

- **做法**：`GET /api/search?q=` 返回命中片段与定位，前端做关键词高亮，可跳到源文件；与模型用的是同一套检索，保证"用户搜到的"和"模型看到的"一致。

### EXT-13 用量与耗时统计

- **做法**：新增 `usage_log` 表，在 6 类调用点记录（chat / tutor / questions / chapter_summary / profile / tips / variant / feynman），字段含 prompt 字数、输出字数、token 估算、首字延迟、总耗时、是否失败。
- **页面**：看板「模型调用与耗时」，含近 7 天柱状图。
- **意义**：`K-3 测试报告` 与《测试执行与性能记录》可以直接引用这里的真实数字。

### EXT-14 导出学习报告

- **做法**：`GET /api/export/report` 现场生成 `.docx`，内容为掌握度总览、今日复习队列、错题与薄弱点、模型调用统计、数据来源说明；docx 由 `extras.build_docx` 手工拼最小 OOXML 包生成，不依赖 python-docx。

### EXT-15 错题变式题

- **做法**：`POST /api/mistakes/{id}/variant`，把原题、正确答案、学生的错误选项、原解析一起给模型，要求同考点换情境；返回的题会按"科目 + 章节名"找对应章节存进去，**找不到章节就只展示不落库**，避免脏数据。

### EXT-16 费曼练习

- **做法**：`POST /api/feynman`，学生写复述，助教按"讲对了什么 / 讲错或含糊 / 缺了什么 / 一句话打分"四段点评，并附检索到的参考资料编号。

### EXT-17 连续学习打卡

- **做法**：`activity` 表按天累计事件（答题、复习评分、正式对话、导入、费曼各计一次）；连续天数从今天（或昨天）往前数。

### EXT-18 增量索引（部分完成）

- **已做**：重新抓取路径上，内容 hash 未变则不重建切片、写作废检索缓存。
- **未做**：`reindex.py` 仍是全量重建。已做与未做都在这里写明，不当作已完成。

## 三、明确没做的

| 项目 | 为什么没做 |
|---|---|
| 引用逐句核验（EXT-19） | 现有 `validate_citations` 只校验"编号是否由服务端发出"，逐句判断"这句话是否真被该片段支撑"需要更强的语义判断；用关键词覆盖硬判会误伤。留待有模型判据时再做，避免做出一个会误报的功能。 |
| 算法可视化动画 | 纯演示向，与"学习闭环"关系弱，工作量不小。 |
| 公式渲染 | 需要引入渲染器或自己写 LaTeX 子集，收益集中在少数科目。 |
| A/B prompt 实验 | 依赖真实 Key 与多次调用，本次全程离线（`--mock`）验证，无法给出可信对照数据。 |
| 多用户与权限 | `users` 表已建但当前是本机单用户；没有真实多用户场景，做了也测不出问题。 |
| 向量混合检索（RRF） | `rag.py` 注释里留了替换点，但 DeepSeek 无 embedding 接口，接外部向量库会破坏"零依赖、离线可跑"的定位。 |
