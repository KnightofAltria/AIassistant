# AI 学习助手软件工程设计文档

版本：v1.1｜修订日期：2026-10-23｜状态：导师汇报与设计评审稿｜团队：3人｜开发周期：8周。

本项目为支持多类课程的 AI 学习助手。学生进入课程后，使用该课程资料获得带出处的回答，通过练习积累学习证据，查看可纠正的误区分析和复习建议。课程维护者审核网络新增资料，发布后生成更新摘要。平台支持远程 API 和本机或局域网模型，手机通过响应式网页与 PWA 使用。

这套文档用于向导师说明我们准备做什么、如何在三人八周内完成，以及用什么证据验收。已确认条件为课程作业、支持多类课程、三名成员和八周周期。试点课程、每周投入时间、硬件和效果指标仍为建议值。示例仓库作为技术参考；当前交付为设计文档，不代表系统和训练已经完成。

## 向导师汇报时如何使用

首次汇报直接使用[15 导师汇报稿](15-导师汇报稿.md)，按“问题与目标—功能闭环—技术路线—三人分工—八周计划—验收与风险”讲解，约8至10分钟。单独的导师汇报版HTML适合投屏或提前发给导师；它不是已完成项目的成果汇报。

导师询问实现细节时，再查阅下表的设计附录。人员和排期以12章为准，功能以01章为准，验收以11章为准。领域微调与RAG分别评价，不能把提示词调整写成已完成微调。

## 交付与范围

提供16份Markdown源文档、独立导师汇报版HTML、完整HTML阅读版、核心OpenAPI 3.1契约及ZIP文档包。汇报版突出项目目标、范围与可行性，完整阅读版保留开发细节。契约用于约束首版核心接口，并非可直接运行的后端。

首版必须完成多课程隔离、带引用问答、练习记录、误区候选与复测、定时收集及审核发布、更新中心、两种模型部署模式、手机适配与安装说明。领域微调保留独立实验里程碑：需有授权语料与硬件，提交训练记录、基线对比和可加载适配器，才能称为完成；若资源不满足，应如实报告未完成，不能用提示词替代微调成果。

暂不承诺所有学科同等准确、手机运行大模型、任意网站自由抓取、视频实时理解、商业级高并发或原生应用商店上架。跨课程通用指业务流程和数据结构可复用，学科资料、评分量规和模型能力仍需逐课验证。

## 已确认条件与工程假设

| 项目 | 初始设计值 | 调整依据 |
|---|---|---|
| 团队与周期 | 3人，8周 | 用户已确认；不设置第4名成员 |
| 时间投入 | 建议每人每周12至15小时 | 待成员核实，共约288至360小时；不等于已承诺工时 |
| 试点 | 3门课程，每课一个章节，6至10名同学试用 | 课程与人数待定；100账号仅作为容量测试上限 |
| 负载 | 20个在线会话，最多5个并行生成 | 超限排队；本地模式单独测量 |
| 资料量 | 每课不超过100份，合计10万切片以内 | 不作为正式容量承诺 |
| 学生范围 | 默认非实名测试账号 | 真实未成年人使用前另行确认政策 |
| 通知 | 站内更新中心 | 外部推送另行实施和授权 |
