## 0. 文档介绍

### 0.1 文档目的

本计划说明计算机课程学习助手（CSLA）要解决什么学习问题、学生如何使用、各端如何运行，以及团队如何完成和核验交付。阅读本计划后，应能沿着“准备资料—获取带出处的讲解—做题与复习—查看掌握情况”的流程理解产品，并知道相应代码、文档和安装包在哪里核对。计划同时明确任务、资源、进度和变更控制，供小组执行与指导教师评审。

## 1. 项目介绍

### 1.1 项目范围

项目是一套面向计算机专业课程的个人学习工具。学生把课件、笔记或开放教材放进自己的资料库，系统先检索相关原文，再用 DeepSeek API 生成带出处的回答、章节讲解和练习。它把“查资料、听讲解、做题、复习错题”接在同一条学习路径上，让学生能回到原始资料核对，而不只得到一段孤立的 AI 回答。

典型使用流程：首次进入后建立本地用户并配置 API Key；在“资料管理”导入 PDF、DOCX、Markdown 或文本，或为新科目选用开放教材；进入“科目学习”选择章节，先看大纲，再逐节生成并保存讲解；阅读后勾选理解状态，按讲解生成题目，提交答案并查看解析；错题进入复习，最后在看板、近期总结和 Word 学习报告中回顾进度。已保存资料与讲义可以在无 Key 时继续阅读。

使用示例：复习《计算机网络》的 TCP 可靠传输时，学生先把课程课件导入对应文件夹，再在“科目学习”中打开相关章节。读到重传机制时，可以打开讲解中的引用核对教材。做完该小节的练习后，如果把超时重传和快速重传混淆，可从错题记录返回解析，复习后再到学习看板查看进度。

功能范围包括：本地账号与个人信息、资料管理和来源引用、AI 聊天、科目与章节管理、分节讲解及独立 Markdown 保存、基于讲解的习题与解析、错题复习与掌握度、学习看板与近期总结、资料辅助操作及设置。内置计算机组成原理、计算机网络、操作系统、数据结构四门课共19章；用户也可建新科目并搜索开放教材。任何 AI 输出都须允许用户查看来源并判断是否适用于课程。

交付形态包括浏览器版应用、Windows x64 与 macOS arm64 桌面封装、Android 8.0+ 本地版。桌面封装双击后启动内置服务；安卓端在手机内运行本地学习库和 WebView 界面，导入、保存及分享通过系统能力完成。各端学习数据保存在本机私有目录，不自动跨设备同步；模型生成和在线教材下载需要网络。

边界：项目不训练模型，不提供离线大模型推理、扫描 PDF 的 OCR、云端同步或高并发教学平台；安卓端使用本地用户，不承接桌面端的远程账号管理。它是课程辅助学习工具，不能替代教材、教师或考试标准答案。外部教材按来源许可使用，引用与模型生成内容由用户核对。

### 1.2 项目目标

目标一：把从资料到练习的闭环做成可操作流程。验收时在新建科目中导入一份可解析资料，检索并打开来源，生成章节大纲与至少一个小节讲解，退出后重新进入仍能读取已保存内容；再生成、作答并删除或重生成一题，查看简要和详细解析。

目标二：让学习进度有依据。阅读勾选、题目完成和错题复习分别留痕，章节掌握度不能仅因做两道题就达到100%；学习看板、近期总结与导出报告应能反映同一份本地记录。目标三：提供可安装交付，按 Windows、macOS 和安卓说明启动，核对资料保存在对应本地目录，退出时服务停止。

验收证据以源码、提交日志、测试记录及实际操作为准。安卓自动化回归在临时数据库中执行，21 项全部通过，应用的共享回归共 80 项，其中 77 项通过，3 项因缺少官方教材缓存而跳过；Windows 和安卓设备上的运行和实际模型生成待按验收清单核查。

### 1.3 客户与最终用户介绍

本项目为课程综合训练，没有商业合同客户；需求提出和最终评审由课程指导教师按课程要求组织。项目小组负责演示系统、提交代码和文档，并说明自动化检查与设备实测的范围。

最终用户是正在学习计算机专业课的本科生。他可能有零散课件、英文开放教材与自己的错题，希望快速定位“这个知识点在哪一节”、获得分步讲解、做少量有出处的题，并在下次打开时接着学。桌面适合整理资料和长时间阅读，手机适合随时复习和查看已保存内容。

用户前提是具备可提取文字的电子资料；AI 生成需要网络、有效的 DeepSeek API Key 及可用额度。需求依据课程目标、现有产品操作流程和项目内部问题记录整理；没有正式用户问卷，不把推测的用户满意度或学习效果作为已测结论。

### 1.4 开发方介绍

开发方为宗思延、邹鑫宇、许知恒组成的课程小组。三人共同维护需求、实现、测试与文档；实际提交和问题处理以 Git 与每日修改日志为准，下面的职责表用于项目协调，不把表格中的计划分工当作全部历史贡献证明。

宗思延：组织需求和交付材料，协调问答与资料检索相关工作。

### 1.5 制约

课程要求保留原文档模板、提交可运行的软件和可追溯的过程记录。技术上，应用使用本机 Python 服务、原生 JavaScript、SQLite 与 DeepSeek API；安卓端增加 Kotlin、WebView、Chaquopy，桌面端封装 WebView/WKWebView。由于模型结果可能出错，引用编号、资料片段、未完成生成和删除操作都要有校验或确认。

外部限制包括教材许可、网络和 API 额度、各设备系统版本，以及不同平台的签名和打包环境。模型内容需联网；未导入资料时不能承诺准确出处；扫描版 PDF 没有 OCR。现有自动化验证不能代替安卓真机、Windows 实机或真实 DeepSeek 调用。工时和现金预算为规划量，实际发生以提交、日志和账单记录。

## 2. 项目过程定义

### 2.1 过程模型

采用小步迭代与可演示版本管理。先让资料导入、检索、聊天和章节学习形成最短闭环，再补齐分节保存、引用、练习、复习与看板，最后进行桌面和安卓封装。每一轮按“需求或问题记录—代码与文档修改—轻量检查—集成验证—提交与评审”推进；问题修复后回归相关流程。

已有过程证据按真实日期分为四段：10月26日至11月1日建立计划与主版本；11月2日至8日完成第二周文档、导航与分节学习改进；11月9日至15日完善掌握度、教材来源并制作中期材料；11月16日至22日整理应用工程，完成安卓迁移和桌面打包。余下课程周用于真机和实机验收、文档核对与答辩，不把未执行的检查提前写成通过。

## 4. 软硬件资源计划

开发和演示资源按实际交付端配置：浏览器版应用需要本机 Python 和浏览器；Windows 便携版、macOS 应用及 Android APK 各有独立构建与验收环境。学生使用时不需要训练 GPU，模型生成由 DeepSeek API 完成。

关键资源是可用的课程资料、网络与模型额度、本地数据目录及目标设备。教材不能仅凭标题认定可用，导入后应检查正文、目录、页码和授权；扫描 PDF 需先取得可提取文字的版本。

开发最低环境以各安装说明为准。Windows 目标为 10 22H2/11 x64，macOS 目标为 Apple Silicon，安卓最低 8.0；构建环境还需要相应 SDK、JDK 或打包依赖。跨平台构建检查与目标机器实际运行要分别记录。

使用阶段准备一台 Windows 电脑、一台 Apple Silicon Mac 和一部符合最低版本的安卓手机，分别走首次启动、导入资料、生成或读取内容、导出报告、退出和再次打开的流程。缺少设备的验收项保留为待验证。

源课件、用户数据库、API Key、个人会话和下载缓存不进入安装包或公开仓库。模型请求只提交完成当前任务必需的问题、上下文与资料片段；用户主动分享或导出时由系统文件选择器指定目的地。
